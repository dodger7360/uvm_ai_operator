# Закупочная цепочка и источники

18.10.2026, №23. Целевое направление владельца; детали результата — для review.
**Сквозного подключения остатков, прайсов и документов к v2 сейчас нет.**
Этот документ не предписывает второй AI pipeline, новую инфраструктуру или
восстановление старого предметного конвейера.

## От позиции до решения сотрудника

Нормализованная позиция → поиск кандидатов в остатках/прайсах → сопоставление
технических характеристик → проверка цены/наличия → результат для сотрудника
и подготовка текста запроса поставщику. Нормализация — [NORMALIZATION.md](NORMALIZATION.md).
GPT понимает написания и смысл; Python хранит доказательства, проверяет структуру
и выполняет точные расчёты. Технический интерфейс matching ещё предстоит спроектировать.

Разрешённые владельцем примеры:

- «Труба Э/С 159х6 ст20».
- «Труба электросварная 159*6 Ст20».
- «Труба 159х6,0 10704».

Поставщик вправе использовать своё написание. Это кандидаты на анализ, не
автоматическое доказательство полного совпадения. В третьем примере нельзя
самовольно дописать сталь и исполнение по двум предыдущим. Неизвестные марка,
тип, стандарт, длина или размер остаются неизвестными; значимые различия видны.
Утверждённой универсальной политики аналогов и замен пока нет.

## Целевой результат сопоставления

Предлагаемая карточка/строка результата, с неизвестными вместо вымышленных значений:

| Сведения | Ограничение |
|---|---|
| Позиция заявки и найденный товар поставщика | Сохранить оба обозначения и связь с исходниками |
| Подтверждённые признаки, отличия, недостающие сведения | Каждое существенное совпадение должно иметь основание |
| Поставщик, город/филиал | Не заменять филиал названием склада |
| Цена, валюта и единица цены | Только если доступны; не сравнивать разные единицы как одинаковые |
| Дата актуальности или получения цены, источник | Дата получения не доказывает дату обновления поставщиком |
| Наличие и количество | Только подтверждённые; цена сама по себе не означает наличие |
| Статус соответствия и объяснение | Написание / подтверждённое совпадение / неполное / возможный аналог — различать |

Неопределённые существенные характеристики исключают автоматический статус
точного совпадения. Текущие цены, остатки и условия не придумываются. Ранжирование,
приоритет цены/логистики, допустимые замены, свежесть и работа с противоречиями —
[открытые вопросы](DECISIONS.md), а не установленные этим этапом бизнес-правила.

### Складской Excel: ранее сформулированные требования владельца

- Лист **`1.ОСТАТКИ`**.
- Колонка **J — «В наличии т»**; колонка **N — укрупнённая метка филиала/города**.
- Название склада из **B** не использовать вместо города/филиала.
- Учитывать требуемое количество; ближайшие филиалы и обсуждавшийся радиус
  **400 км** подлежат предметной проверке, а не становятся готовым фильтром.

Это требования будущего адаптера, не подтверждение чтения рабочего Excel.
До подключения нужны разрешённый образец, проверка версии листа/колонок,
формул/единиц, даты актуальности, соответствия филиалов и определения расстояния.
Правило источника массы и возможность покрытия количества несколькими складами
не утверждены. Производственные файлы в №23 не открывались.

### Справочные знания и техническое сопоставление

Metal Reference — сохранённый внутренний справочный актив, не витрина и не
обязательный второй ИИ. Полезны понятия категории, нормативного варианта, aliases,
технических характеристик с provenance. Устойчивый сортамент отличается от
текущего наличия: нулевой/отсутствующий остаток не исключает товар из сортамента.
**32 категории — исторически согласованный охват прежнего Metal Reference,
не ограничение всего Steel Agent v2.** Сам перечень остаётся в первоисточнике;
расширение/подключение справочника не происходит автоматически.

Reference Data описывают товар и применимые свойства; Market Data — предложения,
цены, наличие, поставщика, город и условия во времени. Разделение по смыслу,
не по URL: одна `/price` страница может содержать оба вида данных. Alias или
категорийный фильтр даёт кандидата, а не подтверждённое совпадение/наличие.
Сохраняются исходное значение, единица, запись/локатор/версия источника,
нормативный вариант и способ получения; непонятые признаки не отбрасываются.

Сопоставление должно различать известное совпадение, значимое различие,
неполноту, конфликт и предложенный аналог. Совместное отсутствие признака не
доказывает совпадение; ограниченный список кандидатов не даёт права выбрать
единственного автоматически. Изменение исходных требований требует повторной
проверки старого предложения аналога. Реестр старых sufficiency/GradeRule и
пять категорий прежнего сравнивателя не становятся схемой или пределом v2.

### Остатки и дефицит

Целевой ответ различает подтверждённый физический остаток, доступность к продаже,
путь, заказанный/неотгруженный объём и дефицит. Не складывать эти показатели
в одно «наличие». Для складского источника утверждено J как физический остаток,
пустое J — неизвестное, не ноль; I/S и расчётные своды не прибавляются к J.
B хранит идентичность физического склада, N — пользовательскую метку филиала;
несколько B в одном N не превращаются в один склад. Специальные статусы площадок,
неизвестная география, доступность к продаже и актуальность требуют подтверждения.

Дефицит считает Python только по сопоставимым подтверждённым количествам и
единицам, с учётом допустимых складов. При неизвестном остатке нельзя заявить
точный дефицит или достаточность. Группировка/повторный импорт не должны удваивать
источники или затирать баланс последней строкой. Политика срезов, суммирования,
резервов и исчезнувших строк остаётся открытой; старый `set_balance` её не определяет.

### Цены, поставщики и бизнес-история

Наблюдаемая цена — значение из конкретного источника/предложения с временем,
валютой, единицей, городом и условиями. История таких наблюдений должна быть
отделима от текущей цены; модель хранения/частота обновления ещё не выбраны.
Факт источника, наблюдение по имеющимся данным и гипотеза сотрудника/GPT
помечаются раздельно. Прогноз цены не является основной целью закупочного продукта.

Данные поставщика из разных источников требуют происхождения полей и актуальности;
схожее имя не оправдывает две независимые или ошибочно объединённые записи.
Парсер предоставляет данные, не принимает закупочное решение. Ни автоматическая
закупка, ни отправка письма поставщику не разрешены существованием адаптера.

Для будущих Excel/PDF/фото нужны ссылки на ячейки/страницы и неопределённости
извлечения. Для Bitrix24 — права на каждое чтение/поиск/изменение и актуальная
ревизия; бизнес-история остаётся там, выборочное использование не равно полной
локальной репликации. Исправление сотрудника в одной заявке не становится
глобальным знанием. Сбор примеров/обучение требуют отдельного разрешения и правил
обезличивания. Для будущей почты ещё предстоит согласовать авторизацию,
подтверждение отправок и обработку неизвестного исхода без автоматического дубля;
историческое предложение «отправлять типовое автоматически» не принято для v2.
