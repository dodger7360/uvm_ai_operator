# Правила разработки Steel Agent v2

Область: ядро v2, его тесты, документация и подключение Telegram.
Корневой AGENTS.md требует прочитать этот файл и при работе вне docs/.

- GPT понимает заявку, номенклатуру и намерение; предлагает коммерческие группы.
- Python хранит данные, считает Decimal, проверяет инварианты и исполняет операции.
- Не добавлять частные Python-правила для марок стали, ГОСТов и типоразмеров.
- Не подгонять модель под буквальное совпадение с одним эталоном.
- Не восстанавливать старую многоступенчатую архитектуру; не переносить B1–B10 автоматически.
- Сохранять оригинал, все исходные позиции и технические отличия; исключать потерю и двойной учёт количеств.
- Коммерческая группировка не означает техническую взаимозаменяемость.
- Не скрывать ошибки, предположения и оставшиеся ограничения.
- Не соглашаться автоматически с пользователем или предыдущим ассистентом при противоречии тестам или технических рисках.
- При разногласии объяснять причину и альтернативу, не менять требования молча.
- Один пронумерованный промпт — один отчёт в reports/.
- Production и deployment требуют прямого разрешения пользователя.
- Реальные API-испытания требуют отдельного разрешения; mock-тесты не доказывают качество модели.
- Продукт: PRODUCT.md; решения: DECISIONS.md; фактическая реализация: ARCHITECTURE.md.
