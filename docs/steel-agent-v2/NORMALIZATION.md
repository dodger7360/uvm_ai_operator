# Нормализация и инварианты

## Этап 6 — теоретическая масса, кандидат 19.10.2026

Исходные м/шт и товарные характеристики не заменяются тоннажем. mass_specs от
того же GPT задают только семантический вид и ссылки на текущие поля/размерные
компоненты. Python выбирает применимую проверенную запись и считает Decimal.
RequestSnapshot.theoretical_mass хранит производную аннотацию item_id: точное
значение, метод, использованные размеры, версию коэффициента, источник и ограничения.
Это расчётная, не фактическая/подтверждённая закупочная масса. Итог по заявке
по умолчанию не выводится; известные исходные количества не суммируются с оценками.

Утверждённое владельцем исправление эталона:
`0,002 × 1,25 × 2,5 × 7850 × 583 / 1000 = 28,6034375 т`, вид `≈28,603 т`.
08пс остаётся основной маркой, Ст3 — допускаемой альтернативой. Расчёт сплошного
листа не переносится на ПВЛ, рифлёный, покрытый лист или другой материал.
Для метров: количество × кг/м / 1000; для штук: количество × кг/шт / 1000
либо количество × длина одного изделия × кг/м / 1000. Общий метраж не длина штуки.
Округление HALF_UP только при показе до 0,001 т; малое положительное значение
отображается `< 0,001 т`, не ложным нулём. Точное значение хранится без округления.

Только для двутавров UVM утвердил расчётную базу 12000 мм без иной длины/резки
и внутреннее основание ГОСТ Р 57837-2017 при применимости к профилю. Эти defaults
не добавляются в исходные факты или ГОСТ товарной строки. Явная длина приоритетна,
резка требует подтверждения схемы и длины готовой детали. Для коммерческой
нормализации балки GPT применяет Ст3 → С255 и 09Г2С → С355, сохраняя raw исходной
марки. Это не общее доказательство взаимозаменяемости и не правило других видов.

После правок qty/размеров оценка пересчитывается, после изменения классифицирующих
характеристик требует новой проверки; неприменимый коэффициент не оставляет старый
тоннаж. Версии/undo сохраняют прежнее основание и точное значение. Новые справочные
редакции не переписывают исторические снимки. calculate_mass — отдельная адресная/
групповая операция; convert_mass по-прежнему только г/кг/т. set/add_quantity принимают
также штуки, без превращения их в единицы массы. Группа фиксируется атомарно.

Проверенные локальные данные применяются без поиска. Новый web-коэффициент проходит
проверку источника, буквальной цитаты, числа/единицы и профиля; он остаётся observed
до отдельного подтверждения пользователем коэффициента и применимости. Разные
значения не выбираются автоматически. Подтверждение связано с event/user/request/
revision, после него Python считает и сохраняет тот же item. Нет replay после
неизвестного исхода поиска и нет записи невалидного плана. Без коэффициента/размеров
позиция сохраняется с объяснением, масса не выдумывается.
Повторный review PR №21: единая проверка резки действует перед kg_per_piece и
kg_per_m для штук длинномера. У kg_per_piece обязательна справочная длина,
совпадающая с эффективной (явной либо 12м UVM только у балки с известным профилем).
340,8 кг/шт относится к 6м 30Ш1, 681,6 кг/шт — к 12м; отсутствие длины запрещено.
Для действительно фиксированного штучного изделия выделен fixed_unit_mass,
не обход через linear/other. Цельный лист не зависит от схемы хлыста.
length_origin сохраняет user/uvm_default. Readonly-показ старой непроверяемой
аннотации не показывает тоннаж и не переписывает исходные снимки.

owner_indicative — отдельный профильный ориентир с approval_scope, источником,
исполнением/ограничениями. CASE-002 допускает 3,36 кг/м без известного ГОСТ;
это не общий процент допуска или разрешение выбирать произвольный сайт.
Неподтверждённый observed автоматически не применяется; несовпадающие технические
факты и противоречащие проверенные коэффициенты требуют уточнения. Неизвестный
ГОСТ остаётся в данных/partial status, не приписывается пользователю.

Расчётные строки компактны: длина 6м/12м и шт. (≈тонны), без дополнительного
метража, пустых строк или ненужных определений. Для листа текущим заданием
прямо сохранено `Лист г/к 2×1250×2500 мм сталь 08пс (допускается Ст3) — 583 шт. / ≈28,603 т`.
Последняя редакция CASE-003 в main сохранена без изменения как отдельный экспертный
текст. Объяснение по запросу содержит точный расчёт, длину/происхождение, метод,
версию коэффициента и ограничения; максимум две кликабельные ссылки BR-007,
полные источники хранятся внутри. CASE-001–006 ещё не загружаются в runtime.
Малый справочник и ограничения — [отчёт этапа 6](reports/stage-6-theoretical-mass.md).

## Отображение — кандидат этапа 3, 19.10.2026

BR-003–005 применяются только к представлению: вид → полная марка → возрастающие
числовые размеры. DisplayLayout от единственного GPT-координатора ссылается на
текущие характеристики; для листа первая роль — толщина. Python не угадывает
сортамент, роли компонентов или размер из индекса профиля. Неизвестные/сомнительные
поля остаются в заявке без вымышленного ключа. Порядок видов не регламентирован;
порядок иных марок не ранжируется. Частный Ст3/09Г2С-15 проверяется на разрешённом
примере, а не становится универсальной таблицей сталей.

display_order(state,layout) задаёт и строки normalized/forward, и Reply.display.
Пользовательский номер относится к последнему доставленному порядку; после правки,
undo и полного показа карта пересчитывается. История/outbox сохраняют текст и карту
атомарно, повтор event_id возвращает сохранённые текст/карту без нового GPT-вызова.
Для старой активной заявки признаки можно получить тем же show-вызовом.
Исходник, originals/provenance, items, коммерческие groups и revisions не меняются
от сортировки/показа. Все строки самостоятельны, без номеров/заголовков/итогов.

Единица массы из общей шапки хранит unit_source_id, указывающий на предшествующий
header, и буквальный unit_text. Допускается только проверяемая каноническая
г/кг/т той же единицы, без пересчёта числа. Старый путь единицы в самой строке
сохраняет прежнюю проверку. При частичном восстановлении сохраняется и header.
Область действия шапки и предметную классификацию определяет GPT; Python проверяет
ссылки/литеральные доказательства, но не доказывает смысл любой шапки.

## Семантическая правка — кандидат этапа 2, 19.10.2026

[BR-010/011](knowledge/BUSINESS_RULES.md) используют сохраняемый порядок товарных
строк normalized/forward, без видимой нумерации. GPT предлагает selection по текущим
полям/размерным компонентам; Python пересекает условия и раскрывает их в устойчивые
ID. Несколько совпадений при cardinality=one или отсутствие совпадений дают уточнение.
Очевидный набор cardinality=all меняется целиком одной версией. Все проверки evidence,
исходника, partition и undo сохраняются; сортировка BR-003–005 не добавлена.

set_quantity устанавливает подтверждённое число/единицу каждой выбранной позиции,
add_quantity прибавляет проверенную дельту (совместимые единицы, точный Decimal).
set_length задаёт отдельное поле length/length_mm/длина в мм из исходного числа
и стандартной единицы длины. Арифметику модели не принимаем как новый источник.
Неоднозначное составное поле длины, неподдерживаемые единицы/пересчёт массы по
геометрии не исправляются догадкой. Изменение марки не разрешает менять размеры,
нормативы, количество или другие факты.

## Глобальные правила — 19.10.2026

Утверждённые [BR-001–009](knowledge/BUSINESS_RULES.md) задают целевое представление:

## Адресные уточнения и единицы массы — №31, кандидат к review

Уточнение может сохранять кандидатов target_ids, поле, уже сообщённое value/evidence,
альтернативы и последний вопрос. Pending привязан к пользователю, request_id/revision,
хранится внутри существующего reply истории без новых SQLite-таблиц. Короткий ответ
интерпретирует GPT; Python не маршрутизирует «да»/«уточнение» по словам. Для применения
прежнего значения требуется точный clarification_event_id и совпадение адресата,
поля, имени, значения и evidence. Иные правки требуют текущего evidence. После
изменения версии или смены темы старое уточнение не является разрешением на правку.
Если не определена единица раскроя, модель должна спросить её, не придумывая единицу.

convert_mass — отдельная операция изменения представления известной массы.
GPT выбирает позицию и единицу; Python пересчитывает г/кг/т точным Decimal с
десятичным коэффициентом, без округления контекстом. Quantity/unit фиксируются
атомарно одной версией, originals сохраняются, undo восстанавливает оба поля.
Пересчёт не требует буквального нового числа в evidence; требуется буквальная
целевая единица из текущего сообщения. Метры/штуки в тонны здесь не переводятся.
Обычный set по-прежнему требует evidence нового значения. Один структурный ремонт
convert_mass не может переключить адресата или заменить постороннюю техническую правку.
Это не разрешение повтора после неизвестного API-исхода.

Качество распознавания коротких ответов и выбора операции живой моделью требует
отдельного Telegram-испытания после согласованного deployment.

## Два результата одной нормализации — целевое поведение

**A. Человекочитаемая заявка.** Краткая профессиональная строка: наименование,
существенные технические характеристики, количество и единица в конце. Текст
пригоден для копирования без удаления служебных вставок. UUID, номер версии,
внутренняя структура групп и заголовок «Заявка, версия 1» в основной текст не входят.
Город показывается, если подтверждён данными. Не повторять объяснения и сведения
без запроса; существенные отличия внутри группы не скрывать. Подробности — по
явному запросу, оригинал и внутренние версии всегда сохраняются отдельно в БД.

«Не требуется уточнений» недопустимо без доказанной полноты характеристик.
Отсутствие вопросов у GPT или `partial=false` само по себе её не доказывает.
Критерии достаточности по видам продукции ещё открыты: [DECISIONS.md](DECISIONS.md).
Кандидат №27 удаляет версию и эту фразу из обычного текста; в production пока
остаётся прежний formatter. Полнота нормализации этим не доказана.

**B. Структурированная товарная позиция.** Данные для будущего сопоставления:

- Вид металлопродукции, наименование/обозначение.
- Размеры и геометрия; марка стали или материала.
- Стандарт/ГОСТ/ТУ, если указан; исполнение или тип, если установлен.
- Длина, раскрой и дополнительные параметры, если известны.
- Количество, единица, оригинальное обозначение и исходное написание единиц.
- Ссылки на доказательства в исходнике; неизвестные и требующие подтверждения признаки.

Это перечень возможных предметных характеристик, а не обязательная анкета каждого
товара. Нельзя заполнять отсутствующие размеры, тип трубы, ГОСТ или длину «по умолчанию».
Необходимость уточнения определяется значимостью для операции; отраслевые правила
обязательности требуют согласования. Отдельная фиксированная схема на каждый
сортамент этим документом не предписывается: нынешний Item имеет общий список
Characteristic и source evidence. Изменение контракта требует проектирования.

Оба результата используют одни подтверждённые факты. Красивое представление не
должно менять заявку, её original, количества или технические различия.
Нормализация помогает узнавать одну номенклатуру в разных написаниях, сохраняя границы:

| Результат | Что означает |
|---|---|
| Нормализация написания | Разное написание приведено к читаемому виду; это ещё не доказательство совпадения |
| Подтверждённое техническое совпадение | Существенные признаки проверены по источникам и согласованному критерию |
| Неполное совпадение | Недостающие сведения явно указаны; требуется проверка |
| Возможный аналог/замена | Отличия известны, допустимость замены отдельно подтверждается |

Критерии соответствия и замен пока открыты. Похожесть названий и коммерческая
группа не являются доказательством взаимозаменяемости. Примеры приёмки —
[NORMALIZATION_CASES.md](NORMALIZATION_CASES.md); будущие источники —
[PROCUREMENT_PIPELINE.md](PROCUREMENT_PIPELINE.md).

## Реализованные инварианты и их границы

GPT выделяет исходные позиции, нормализует характеристики и предлагает группы.
Python не решает эквивалентность стали или ГОСТов.

Оригинальный текст неизменен. SourceRecord задаёт диапазон Python Unicode
[start,end), kind product/header/note/unresolved. Все непустые символы покрываются
ровно один раз; диапазоны не пересекаются. Каждому product соответствует один
Item со стабильным ID и source_id. Повторяющиеся строки сохраняются раздельно.
Характеристики содержат raw и ссылки source_ids; literal evidence проверяется.
Количество — конечная неотрицательная Decimal из исходного numeric fragment;
unit/unit_text сохраняют исходное обозначение. Неизвестное не считается нулём.

Коммерческая группа ссылается на item_ids. Совокупность групп содержит каждую
позицию ровно один раз. Суммы не принимаются от GPT: Python суммирует Decimal и
приводит совместимые единицы, например кг к тоннам. Метры/штуки не превращаются
в тонны без источника массы. Неизвестные единицы выводятся отдельно.
Различия характеристик и единиц вычисляются буквальным сравнением. В кандидате
№27 обычный текст сохраняет полные строки участников, а рассчитанные различия,
замечания модели и предупреждение о взаимозаменяемости доступны в explanation.
Подпись группы не заменяет технические требования; краткость не разрешает замену.

Адресные изменения: set по target_id, regroup полного набора прежних ID, undo
последней правки. Ожидаемые id/revision защищают от устаревшего плана. Значение
правки требует evidence в текущем сообщении. Несовместимые операции отклоняются
целиком; новая версия сохраняется только после проверки всего результата.
Undo создаёт новую revision, восстанавливая прежний снимок и стек отмен.
Исходные значения остаются в originals и версиях; discussion/search их не меняют.

При существенной неоднозначности модель должна уточнить вопрос. Неизвестные
характеристики/количества, unresolved и вопросы видимы как partial. После одного
неудачного ремонта старое состояние сохраняется, оригинал сообщения остаётся
в истории либо inflight при сбое SQLite.

Границы проверки: покрытие символов не доказывает правильность классификации
product/note; наличие raw не доказывает семантическую верность value или полноту
извлечённых характеристик. Эти ошибки оцениваются по исходнику в живых испытаниях,
а не добавлением каталога частных правил. Undo действует внутри текущей заявки;
возврат к предыдущей архивной заявке пока не реализован.

  похожего общего названия. Неизвестный смысл индекса не мешает сохранить его
  буквально и не разрешает выдумать расшифровку. Это не словарь замен сталей.
- **Все нормативы.** Сохранять каждый записанный ГОСТ/ТУ/СТО, редакцию и отношение
  к позиции. Не выбирать один норматив «представителя» вместо остальных и не
  дописывать год. Роль документа/применимость не устанавливаются по одному номеру.
- **Шапки и строки.** Общая шапка — контекст, не товар. Её признаки относятся
  только к доказанной области действия; новая шапка не меняет предыдущий блок.
  Доказательства включают строку и шапку, исходник не разворачивается поверх
  оригинала. Переносы внутри одной логической позиции не создают новый товар;
  повторяющиеся самостоятельные позиции не исчезают. Неоднозначная область
  или числовая строка не удаляется ради успешной проверки.
- **«Или».** Явно разрешённые варианты марки/раскроя сохраняются как связанные
  альтернативы одной потребности. Нельзя выбрать вариант или удвоить количество,
  превратив варианты в независимые потребности. Несколько признаков без ясного
  отношения требуют уточнения. Представление альтернатив внутри v2 ещё требует
  проверки/проектирования, а не копирования старого скалярного поля.
- **Условия подбора.** Длина, мерность, диапазон, раскрой, стенка, покрытие,
  прокатка и форма поставки сохраняются вместе с областью/условием, а не только
  коротким названием. Для трубы нельзя домыслить способ изготовления по одному
  ГОСТ; для профиля — геометрию по похожему индексу; для листа — недостающий
  раскрой. У фитинга связь «к этой трубе» не доказывает DN, давление, стандарт,
  угол или совместимость. Контекстная гипотеза должна отличаться от буквального
  требования, неоднозначный адресат остаётся неустановленным.
- **Количество и единица каждого источника.** Различать длину изделия и величину
  потребности, исходную массу и расчётную аннотацию. Пробелы/NBSP в числе не
  разрешают потерю разрядов. Дубли требуют отдельных источников; повторное
  построение представления не суммирует уже подсчитанные итоги. Кг↔т — точное
  преобразование одной размерности; м/шт/м² не превращаются в массу без основания.
  Предпочтение отображения не округляет сохранённую Decimal-потребность.
- **Адресные ответы.** Номер отображения не заменяет устойчивую связь с исходной
  позицией. При неоднозначной группе уточнить адресата; количество группы нельзя
  произвольно распределять по участникам. «Да» относится только к определённому
  актуальному предложению, не разрешает новую марку или глобальное правило.
  Правки на копии атомарны; обсуждение/показ не создают версию. Undo v2 — новая
  версия, восстановление исходного поля не следует считать тем же действием.

Дубли и коммерческие группы остаются разными понятиями: сохранение отдельных
источников обязательно; автоматическое суммирование идентичных строк и сортировка
по прежней таблице видов **не перенесены как утверждённая политика v2**.
Карта конфликтов и решений — [DECISIONS.md](DECISIONS.md).

### Масса: не смешивать четыре результата

Исходное количество пользователя, нормативная теоретическая масса по применимому
документу, расчётная оценка по геометрии/допущению и фактическая масса партии —
разные сведения. Для производного результата нужны метод, входы, единицы,
источник/вариант, условия применимости и статус достоверности. Ни оценка, ни
данные поставщика не переписывают исходную потребность. Неизвестный коэффициент
не берётся из памяти GPT. Источники: [METAL_REFERENCE](../METAL_REFERENCE.md),
[NORMALIZATION_STAGE_ONE](../NORMALIZATION_STAGE_ONE.md).

Старые узкие допущения для листа Ст3 и А240 Ø12 сохраняются в прежних материалах
и коде как актив для проверки. Их наличие/историческое разрешение в старом
контуре не включает расчёт в v2 и не подтверждает нормативную применимость к
любой поставке. Перенос метода, охват категорий и округление требуют отдельного
решения; обязательный маршрут через онлайн-калькулятор или Metal Reference не вводится.

## Экспертные поправки и знания

Процесс №26 — [knowledge/README](knowledge/README.md). GPT сначала обрабатывает
всю сырую заявку, после замечаний повторно выдаёт весь исправленный результат.
Поправка распространяется на подходящие позиции текущего CASE, но не становится
общим правилом без отдельного утверждения. Предметный факт требует источника и
применимости; approved-кейс не доказывает всеобщую техническую эквивалентность.
Знания должны помогать извлекать характеристики, не подменять Python-проверки
полноты, точности и источников. Неполнота Metal Reference не блокирует понятный товар.
Подключение нового каталога к работающему Telegram в №26 не выполняется.

## Частичный результат и исправления — кандидат №28

Понятная труба с размером 159×6 и количеством 240 м остаётся трубой в метрах.
Неизвестные марка, норматив, исполнение или масса не являются структурной ошибкой.
Критически неизвестные/противоречивые значения и адресные вопросы не скрываются;
при value=null formatter также сохраняет raw неоднозначного обозначения.

Один ремонт GPT получает конкретную ошибку и прежнее предложение. После двух
структурных сбоев recovery.py проверяет независимые позиции новым вызовом тех же
инвариантов: неоднозначные IDs/перекрытия/неверные доказательства не принимаются,
все непроверенные непробельные фрагменты покрываются unresolved. Некорректные
характеристики не удаляются механически. Итог ещё раз валидируется целиком по
неизменённому оригиналу. Невалидная коммерческая группировка не применяется:
восстановленные позиции получают отдельные нейтральные группы с вопросом.

Нет надёжных позиций — нет RequestSnapshot. Исходник сохраняется в steel_v2_turn
с pending_source, доступен после перезапуска вне ограниченного окна переписки.
Если прежняя активная есть, она не заменяется локальным восстановлением неудачной
новой: её проверенная часть хранится в Reply.pending_snapshot и показывается как
ещё не активная. Для продолжения требуется явный выбор сохранённого исходника
через pending_event_id; во время ремонта менять этот источник нельзя. При двух
сбоях продолжения оригинальная pending-запись не заменяется коротким «продолжи».

Set/regroup/undo сохраняются. Дополнение resolve разрешает **существующий**
unresolved: новые records только внутри его абсолютного диапазона, новые originals
только из сохранённого original_text; прежние originals/ID не изменяются. Новые
позиции сохраняют устойчивые ID. Начиная с этапа 3 новый полный показ сортируется
заново, поэтому номера определяет обновлённая карта отображения. Все coverage,
source references, количества и групповой partition проходят полный validate.
Set после resolve в том же плане может применить явную поправку из сообщения;
вся операция — одна версия/транзакция, undo возвращает и unresolved.

Для части составного признака set.characteristic может иметь replace_from:
единственный буквальный токен прежнего значения заменяется на value, подтверждённое
evidence текущего сообщения. Это точная строковая операция, без знания сортамента;
двойное вхождение/неподтверждённое значение отклоняются атомарно. Все затронутые
составные/отдельные признаки GPT обязан адресовать согласованно, а неоднозначность
уточнить. Python не доказывает полноту семантических связей любых характеристик.
Форматирование по просьбе — существующий readonly custom; постоянные предпочтения
этим не вводятся. Подробности/ограничения — [№28](reports/028-partial-normalization-and-corrections.md).

Итоги частичной заявки — только известная часть: unresolved не включается в сумму
и это явно сообщается пользователю и модели. Уточнение итога не создаёт новую версию.
