# Типизированная единица при создании — блок 4.4, кандидат

Решение владельца от 22.10.2026; реализация ожидает review, не deployment.
Этот документ дополняет [решения](DECISIONS.md). NORMALIZATION.md остаётся
неизменным источником approved-пакета: здесь его artifact не пересобирается.

create_request может нести один unit_proposal: конкретный target_id, каноническую
unit и question. Это не evidence: у целевого extraction item и его original нет
подтверждённой единицы/unit_text/unit_source_id. Единицы других строк не дают ему
такого факта. Допустимы канонические единицы существующих измеряемых операций:
т, кг, г, м, мм, см, шт. Предложение сохраняется в PendingClarification вместе с
request/revision/event в прежнем Reply, атомарно со snapshot/outbox.

Явное согласие GPT выражает отдельным confirm_unit в edit_request с точными
expected_request_id/revision и clarification_event_id. Разрешена ровно одна
операция: тот же target/unit и буквальная цитата всего текущего ответа. Python
не распознаёт слово «да» и не подставляет предлагаемую единицу как source evidence.
Обычный set остаётся под прежними проверками. В changes записываются цитата ответа
и confirmation_event_id; originals/source/unit_text остаются исходными.

Снимается только связанный question, remaining_questions override запрещён.
Неоднозначный ответ — clarify без мутации, с сохранением того же предложения.
Отказ/другая тема, неуспешное подтверждение, новая версия/заявка и undo не позволяют
впоследствии использовать старую ссылку. Успешное подтверждение создаёт одну новую
версию, повтор Telegram update не повторяет вызов/запись. Старые clarify/evidence
контракты не ослабляются; универсальная система вопросов не добавляется.

Синтетические SDK HTTP-тесты доказывают исполнение готовых планов и сохранность,
а не самостоятельное понимание GPT. [Отчёт](reports/block-4-4-create-unit-confirmation.md).
