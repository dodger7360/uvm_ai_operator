# Шаблон эталонной заявки — не утверждённый CASE

Скопировать в новый `CASE-YYYYMMDD-NNN.md` только для предоставленного владельцем
материала. Шаблон не является тестом, заявкой или записью об утверждении.

## Паспорт

- CASE ID / группа / дата: заполнить.
- Статус: proposed; approved только после явного утверждения **всего** результата.
- Разрешение публикации: материал явно предоставлен владельцем для этого процесса;
  зафиксировать основание без секретов и лишних персональных данных.
- Версия знаний: commit H и ID/редакции фактически использованных правил/фактов.
- Ограничения / открытые вопросы / связанные кейсы: заполнить либо явно «нет».

## 1. Исходник

Полный первоначальный текст разрешённой заявки, без редакторского исправления.
Не подставлять production payload. Если требуется обезличивание — согласовать
публикуемую версию; не объявлять её неизменённым исходником production.

## 2. Первая самостоятельная нормализация GPT

Весь первый результат до замечаний владельца, включая вопросы/неизвестные параметры.
Владелец не должен готовить эту версию сам.

## 3. Итерации и замечания владельца

Для каждой итерации: конкретное замечание, область поправки, какие позиции/группы
затронуты, полный повторно выданный результат. Сохранить первую версию и исправления,
не оставлять только идеальный финал. Не переносить постороннюю переписку.

## 4. Сопоставление исходных и итоговых позиций

| Исходная позиция / фрагмент | Существенные характеристики из источника | Исходное количество / единица | Итоговая строка / количество | Исправление и основание | Неизвестное / подтверждение |
|---|---|---|---|---|---|

Заполнить для **каждой** товарной позиции, включая общие шапки и альтернативы.
Сохранить оригинальные обозначения, марки, все нормативы, размеры/исполнение и
прочие существенные различия. Точные количества — строкой без float/округления;
исходные единицы не терять. Различать источник, вывод и замечание владельца.
При группировке перечислить участников; каждая позиция учтена один раз.
Разделение/объединение количеств должно иметь явное основание, не скрывать различия.

## 5. Итоговый текст

Весь профессиональный текст, утверждённый владельцем, готовый к копированию.
Сохранить существенные неизвестные/уточнения. Утверждение текста не доказывает
техническую взаимозаменяемость или нормативный факт.

## 6. Подтверждение и правила

- Явное утверждение владельца: формулировка, дата, область (весь CASE или частичная
  правка). До утверждения всего CASE статус остаётся proposed.
- Отдельно утверждённые **общие** правила: ID/редакции и свидетельство отдельного
  согласования; если нет — «нет». Предложенные обобщения перечислить как proposed.
- Проверка полноты/количеств/источников: что проверено и какие ограничения остались.
- Исправления после утверждения: новая редакция, причина и новое подтверждение;
  историю не удалять. Старый Git-коммит сохраняет предыдущий эталон.
