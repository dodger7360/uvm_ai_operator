## Исправленный эталон и четыре первоначальных падения

Владелец отдельно подтвердил замену ошибочного 28,6014375 т на **28,6034375 т**,
показ после компактного пересмотра **≈28,603 т**. Все активные assertions исправлены.
Коэффициенты не менялись.

```text
0,002 × 1,25 × 2,5 × 7850 = 49,0625 кг/лист
49,0625 × 583 / 1000 = 28,6034375 т
49,0625 × 600 / 1000 = 29,4375 т
```

Независимые Decimal (precision=50) и Fraction дали 91531/3200 т. Три падения
происходили из-за неверного expected, арифметика была правильной. Четвёртое:
SearchUnavailable наследует ValueError и попадал в ремонт edit-плана. Отказ поиска
вызывал лишний coordinator-вызов и допускал повторное вхождение в поисковую ветку.
Теперь поисковая стадия имеет terminal-обработчик, не возвращается в structural
repair. Неизвестный исход по-прежнему карантинируется прежней очередью.

## Расчёт и отображение

| Сценарий | Точный тоннаж | Вывод количества |
|---|---:|---|
| Лист 2×1250×2500 мм, 583 шт., 7850 кг/м³ | 28,6034375 | 583 шт. / ≈28,603 т |
| Тот же лист, 600 шт. | 29,4375 | 600 шт. / ≈29,438 т |
| Труба э/с 159×6, Ст20, 240 м × 22,64 кг/м | 5,4336 | 240 м (≈5,434 т) |
| Балка 30Ш1, С255, 40 шт. × 12 м × 56,8 кг/м | 27,264 | 40 шт. (≈27,264 т) |
| Та же балка с явной длиной 6 м | 13,632 | 40 шт. (≈13,632 т) |

Formatter разрешённого исходника:
`Лист г/к 2×1250×2500 мм сталь 08пс (допускается Ст3) — 583 шт. / ≈28,603 т`.
Исходные quantity/unit, originals, source records и коммерческие группы сохранены;
нет второго товара, обязательной Ст3, нумерации/заголовков или общего итога.

Поддержаны м × кг/м; шт. × кг/шт; шт. × длина одного изделия × кг/м. Единственная
геометрическая формула — обычный сплошной лист углеродистой стали. ПВЛ/рифлёный/
покрытый лист не должен классифицироваться GPT как solid_carbon_sheet. Python
не создаёт второй распознаватель сортамента; живое качество классификации не доказано.
Идеальные формулы труб, балок, швеллеров или уголков не вводились.

Только для двутавров действует утверждённая база 12000 мм без другой длины/резки.
Явная длина приоритетна; неизвестная длина и неразобранная схема резки исключают
default. Подтверждённая длина готовой детали допускается отдельным режимом.
Общий метраж не длина штуки. Внутреннее основание ГОСТ Р 57837-2017 не добавляется
в товарный ГОСТ или originals. Коммерческие Ст3 → С255, 09Г2С → С355 заданы тому
же GPT только для двутавров с сохранением raw, не как всеобщая техническая замена.

Decimal-умножение и масштабирование точные, с независимым localcontext. HALF_UP
до 0,001 т применяется только к выводу; малое положительное значение показывается
`< 0,001 т`, а не ложным нулём. Внутренний тоннаж не округляется.

## Коэффициенты и происхождение

MassSpec от прежнего координатора содержит стабильный item_id и семантические
ссылки на текущие характеристики, не результат арифметики. MassCatalog — read-only
инъецируемый интерфейс. MassReference хранит ID/revision, вид, профиль/размеры,
нормативы, марки, единицу, метод, источник, дату, статус, ограничения и при кг/шт
длину штуки. Seed mass_reference.json содержит три узкие записи:

- Плотность 7850: [Е-Металл](https://e-metall.ru/utility/calc/list/) описывает метод
  обычного листа; [Берлион](https://berlion.ru/calculator) отдельно оговаривает
  другие методы ПВЛ/рифлёного. Начальные марки — 08пс/Ст3. Это расчётное допущение.
- 22,64 кг/м: [Уралтрубпром 159×6](https://trubprom.com/products/catalog/esv/round-pipes/159/159x6).
  Начальный scope — Ст20/20, заданная электросварная геометрия и совместимые
  нормативы; не иная технология, покрытие или фактическая масса партии.
- 56,8 кг/м: число условного эталона совпадает с индексированной строкой
  [каталога ЕВРАЗ](https://ese.pro/upload/iblock/f86/374qczwmu8qmaa4vv33qlovyjcq5wvwv/Katalog_produktsii_evraz.pdf).
  Прямое чтение PDF вернуло 403. Полное чтение и актуальность нормативного статуса
  не заявляются; основание 2017 года задано владельцем для номинальной оценки.

Reviewed не означает сертификат поставки. Большого каталога/новой БД нет.
Старый Metal Reference изучен чтением: schema имеет provenance, но reader зависит
от legacy normalizer, часть значений хранится REAL. Эти зависимости/float не
перенесены. Будущий SQLite-адаптер может выдавать точные MassReference без изменения
арифметики. Реальных записей кг/шт seed не содержит; интерфейс проверен синтетикой.

## Версии, правки и атомарность

RequestSnapshot.theoretical_mass — аннотации item_id со спецификацией, отпечатком
классифицирующих фактов, точным тоннажем, размерами и полной копией версии основания.
При qty/размерных правках читаются новые значения; при смене марки/профиля/норматива/
исполнения нужна новая проверка класса. Неприменимый коэффициент не оставляет старый
тоннаж. Кг/шт для одной длины не переносится на другую. При нехватке данных
позиция и количество сохраняются с объяснением, масса не выдумывается.

calculate_mass использует прежние target_id/selection и карту последнего показа.
set/add_quantity принимают также шт.; convert_mass остаётся только г/кг/т.
Аннотации вне выбранного набора запрещены. Чистый расчёт не может убрать товарные
вопросы. Change хранит точные before/after, версии — полное основание; undo и restart
сохраняют число и коэффициент. Обновление seed не переписывает старые версии.

Нет DDL/миграции: только совместимые поля прежних JSON snapshot/Reply. Старые
записи имеют пустые defaults и прежнюю сериализацию. Repository.finish/finish_hook
атомарно фиксируют версию/историю/результат/готовый outbox. Queue/runtime, HTML
доставка, сортировка/ID-карта, роли и typing не меняются. Ограниченные изменения
текста formatter описаны выше; HTML-пакетирование и durable outbox прежние.

## Поиск связан с изменением состояния

Явный mass-only edit с search_query использует существующий search, затем один
ограниченный plan-вызов того же GPT для извлечения evidence. Нет нового ИИ или цикла
поиска. Известным проверенным коэффициентам дополнительный поиск не нужен.

Python требует URL из SearchAnswer.sources, буквальную цитату, число рядом с
правильной единицей, профиль/размеры и заданный норматив. Не допускаются профиль
из одной строки и число из другой, перепутанные кг/шт и кг/м. Для нового кг/шт
длинномерного изделия обязательна цитируемая длина справочной штуки, совпадающая
с явной длиной либо разрешённым default балки. Но это проверка
согласованности evidence, не доказательство технической истинности сайта.

Поэтому новые интернет-значения **не применяются автоматически**: observed-кандидаты
сохраняются в PendingMass существующей истории, показываются с BR-007 ссылками
(максимум две), условиями и просьбой подтвердить коэффициент/применимость.
Противоречия сохраняются раздельно. Подтверждение выбирает конкретный candidate ID
и связано с user/request/revision/event; Python считает и фиксирует ту же позицию
без нового поиска. Известные и новые оценки группы применяются одной версией.
Поздняя неудача поиска, другая ревизия/пользователь или незавершённая доставка
не позволяют применить старое предложение. Источники остаются в активной аннотации
для аудита, исходный ответ исследования — в прежнем private search_text.

Локальный расчёт/нормализация: один coordinator-вызов. Новое исследование:
coordinator + search + evidence coordinator. Подтверждение: один coordinator,
без search. Все проходят прежний AttemptTransport; неизвестные исходы изолируются
без replay. Exactly-once внешнего API не обещается; автоматической отправки
сообщений/платных API-тестов не было.
