## Воспроизведённые причины и патч

### A. Предметное уточнение

AgentPlan может вернуть clarification с адресатами, field/name, value/evidence,
альтернативами. Агент проверяет ссылки на текущие позиции и буквальный источник.
PendingClarification хранится в существующем Reply/steel_v2_turn атомарно с историей:
исходная команда, event_id, request_id/revision, предложение и последний вопрос.
Новых таблиц/миграций нет. Старые Reply без нового поля сохраняют прежние JSON bytes.

Repository читает только последнее уточнение текущего пользователя/версии.
Короткий ответ поступает той же GPT вместе с pending_clarification. Regex/keyword
router не добавлен. GPT решает, подтвердил ли ответ адресата; если нет — один короткий
конкретный вопрос. Уточнение единицы не требует повторного выбора адресата/значения.

Для переноса прежнего evidence требуется clarification_event_id. Python разрешает
только совпадающие адресат/поле/имя/значение/evidence; другие изменения требуют
текущего evidence. Подтверждающее сообщение остаётся в истории Change отдельно
от evidence исходной команды. После успешной мутации/смены версии/темы контекст
не используется как старое разрешение. При failed validation/таймауте контекст
сохраняется, автоматического повтора API нет.

Синтетические диалоги: исходный раскрой 2х6 → неоднозначное короткое подтверждение
→ конкретный вопрос → только вопрос о единице → применение уже сохранённого 2х6.
Проверены ответы «Уточнение», «Да», «Относится», reopen, rejected scope и undo.
Это scripted fake/SDK mock: качество выбора намерения живой GPT ещё не принято.

### B. Стандартные единицы массы

Старый контракт имел только set/regroup/undo/resolve. Для set.quantity Python
проверяет буквальное новое число — пользователь, просящий пересчёт, его не называл.
Это воспроизведённый дефект пути, совместимый с живым симптомом; идентичность
живому первому плану не доказана.

Добавлена отдельная convert_mass: GPT передаёт target_id, целевую единицу и её
буквальное обозначение из сообщения; нового вычисленного числа в плане нет.
Python проверяет известные исходные quantity/unit и стандартные единицы г/кг/т.
Decimal строится с точным изменением десятичного показателя, без округления
глобальным decimal context. Quantity/unit — одна атомарная версия и два Change.
Originals, исходные количества/характеристики, группы и остальные позиции сохраняются.
Undo восстанавливает оба поля. Метры/штуки/неизвестная исходная масса отклоняются.

Синтетический пример: 1375 кг → 1,375 т. Чистая арифметическая проверка включает
также 1250 кг → 1,25 т. Фикстура из пяти позиций вымышленная, production-строки
или GPT payload в Git не переносились.

При невалидном старом set-плане допускается прежний единственный структурный ремонт,
теперь с явной инструкцией convert_mass и точной диагностикой. Ремонт не может
переключить адресата или превратить другую техническую правку в пересчёт.
После двух ошибок активная заявка не меняется; третьего API нет.
Никакого локального арифметического доверия к числу модели и общего ослабления set.
