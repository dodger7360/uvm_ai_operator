## Реализация BR-010

Выявлено расхождение: render обходил groups/item_ids, а display_numbers строились
по items. После regroup третья показанная строка могла иметь иной ID, чем третья
исходная позиция. Исправлен именно этот путь, новая сортировка не добавлена.

presentation.display_order — единая последовательность товарных ID текущего
normalized/forward. Печатная нумерация удалена; внутренние ID не меняются.
Переносы внутри одного товарного описания превращаются в пробелы в отображении,
original_text и исходные характеристики при этом не переписываются.

Reply.display сохраняет request_id/revision/item_ids вместе с историей и
прежним outbox. Repository.last_display читает последнюю подходящую карту
пользователя, проверяет версию и полный состав ID. Для durable Telegram-событий
принимается только delivered: неподтверждённая/отозванная доставка не считается
показанной. При неизвестной доставке прежний queue fence остаётся действующим.

Создание, edit/undo и повторный normalized/forward обновляют карту. Original,
totals, custom и pending-часть ещё не активной заявки её не переопределяют.
Старая история без карты требует нового показа; к items/исходным номерам нет fallback.
Никаких новых таблиц, миграций, группировок или алгоритмов сортировки.

## Реализация BR-011

Тот же GPT получает текущую заявку и предлагает Operation.selection:
- display — позиции последнего показа;
- where — пересечение условий по label и существующим Characteristic;
- all — все подходящие позиции по явно распознанному общему намерению;
- cardinality=one/all определяет необходимость одного кандидата или всего набора.

Python разрешает критерии в ID, а не доверяет отдельному списку ID модели.
Пустое совпадение и несколько совпадений при one дают короткое уточнение без
изменения состояния и без дополнительного API-вызова. All применяется ко всему
совпавшему набору без требования слова «все».
Внутренний прежний target_id сохранён для совместимости и подтверждений pending;
selection и target_id одновременно запрещены контрактом.

Сравнение — полное значение либо целое обозначение товарного label. Для составного
размера GPT указывает существующее поле, буквальный разделитель и 1-based компонент.
Python сравнивает ровно этот компонент; «8» в ширине не заменяет толщину.
Предметный смысл компонента определяет GPT, Python не содержит правил сортамента.

set_quantity задаёт число/единицу каждой выбранной позиции. add_quantity считает
точную прибавку в совместимых стандартных единицах, сохраняя единицу позиции.
set_length переводит исходное число/единицу длины в мм для отдельного поля
length/length_mm/длина. Вычисленный результат модели не принимается вместо
буквального evidence. Известные исходные величины и коэффициенты проверяет Python.
Пересчёта метров/штук в массу и справочных коэффициентов нет.

PendingClarification может сохранить всю неразрешённую операцию, включая unit и
unit_evidence. Подтверждение применяется только к её кандидатам и прежнему
значению/полю; остальные правки требуют evidence текущего сообщения.
Весь раскрытый набор операций проходит прежние invariants и один commit.
Перекрывающиеся противоречивые правки, несовместимые единицы и другие ошибки
не оставляют частично записанной заявки. Repair семантического плана не может
сменить разрешённый набор ID, поле или вид операции.
Сохранено узкое исключение №31: ошибочные set.quantity/unit можно заменить
convert_mass для ровно тех же ID, без других технических правок.

## Воспроизведённые сценарии

Синтетический набор: три листа, швеллер, арматура, профильная и круглая трубы;
порядок коммерческих групп намеренно отличается от items.

| Команда / случай | Проверенный результат |
|---|---|
| «Лист сделай Ст3» | Все листы; швеллер и остальные виды неизменны |
| «Лист 8 сделай Ст3» | Толщина 8 мм, не ширина 8, не швеллер 8П и не позиция 8 |
| Два листа 8 мм с разными марками/нормативами | Меняется только указанная марка обоих; размеры/нормативы/количества и отдельные ID сохранены |
| Составные размеры с ×, х, * | Сравнивается первый заданный компонент, не любое вхождение цифры |
| «На всё поставь Ст3» | Все позиции выбранного набора, одна версия |
| «Лист в итоге нужен 50 т» | По 50 т каждому выбранному листу, без суммарного вывода/деления |
| «Арматуру добавь 7 т» | 2,125 + 7 = 9,125 т; повтор event не прибавляет снова |
| Прибавить 7 т к 17,25 кг | 7017,25 кг точно; не 7 кг и не замена старого количества |
| Профильная труба длиной 6 м | Отдельная длина 6000 мм; круглая труба и её параметры неизменны |
| Позиция 3 после show/edit/reopen/undo | Третья показанная строка, в тесте i6, а не i3 из items |
| Неоднозначный выбор одной позиции | Вопрос; значение/операция сохраняются до уточнения |
| Пересекающиеся противоречивые признаки | Пустой набор, уточнение, не расширение выбора |
| Ошибка группового изменения / смена scope в repair | Активная заявка/версия неизменны |
| Undo групповой правки | Полное восстановление прежних items и сохранённые версии |
| Два пользователя с одинаковыми item IDs | Состояния и карты не смешиваются; чужой request/revision отклонён |
| Unknown доставка | Новый ответ не принят за последний показанный |

Тестовые планы поставлены fake GPT: они доказывают разрешение/применение операции,
а не способность живой модели всегда верно построить критерии по русской фразе.

## Гарантии и ограничения

Для нового selection-пути Python исключает выход за набор, точно удовлетворяющий
проверенным условиям, либо за конкретные ID последнего подтверждённого показа.
Нельзя незаметно подставить исходный номер, пропустить одного из all-совпадений,
сменить адресатов во время ремонта или записать только часть группы.

Это **не абсолютная гарантия понимания намерения GPT**: ошибочно выбранные моделью
критерии/семантический режим остаются риском до живой приёмки. Прямой target_id —
совместимый прежний контракт v2 для вызовов ядра и подтверждений PendingClarification. Для текущего GPT
предписан selection; непредметные сомнения требуют уточнения.
Техническая защита не должна выдаваться за доказательство отсутствия любых ошибок ИИ.

Открыт случай распределения единой общей добавки между разными товарами:
автоматического распределения нет, без определённого набора/прибавки на позицию
требуется уточнение. Не установлены новые правила такого распределения.
Нестандартные поля длины, противоречивые составные значения и неизвестные единицы
не переводятся догадкой. Штуки и справочная масса не расширялись.
BR-003–005, HTML и компактные источники остаются отдельными задачами.

Production/Windows/.env/рабочие SQLite не изменялись, main напрямую не менялся.
Один агент v2, прежний durable outbox и polling сохранены. Merge/deployment не выполнялись.
