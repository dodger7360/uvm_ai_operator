## Причины и изменения

1. `presentation.render()` использовал технический вывод для каждого обычного
   ответа: UUID, source ID, rationale и полные notes. Теперь обычный вывод
   компактен, технические характеристики и точность количеств сохраняются.
   Подробности доступны через explanation, исходник через original.
2. В контракте не было вида текста для пересылки; show_request всегда попадал
   в тот же formatter. Добавлены readonly view forward/custom/search_status.
   Forward детерминированно использует текущие структурированные данные.
   Custom использует answer того же координирующего вызова, без изменения заявки.
   Никаких regex-маршрутов пользовательских фраз или категорий металлопроката.
3. Поиск запрашивал action.sources, но вообще не читал его. Успешный ответ с
   такими источниками и без annotations ошибочно отклонялся. Аналогично не
   учитывались документированные weather feeds без URL. Обе ошибки воспроизведены
   настоящим SDK поверх mock HTTP и исправлены. Учитываются также URL завершённых
   open_page/find_in_page. Проверки завершения инструмента и источников сохранены.

Безопасная проверка последних production-событий дала web_search model_call
reason=null, затем search_unavailable/validation_error. Это подтверждает локальное
отклонение после API, но не различает отсутствие tool/source/text. Конкретная
форма старого ответа неизвестна: body не журналировался. Нельзя утверждать, что
именно feed или action.sources был причиной того погодного отказа.

## Диагностика

Добавлены allowlisted причины no_tool/tool_incomplete/no_sources/empty_text/
invalid_response/incomplete_response/api_error/unknown; числа источников и feeds,
факт завершения инструмента, доступный request ID. Прежние HTTP status/code/param
сохраняются для ошибок API. Произвольные exception messages и тела не сохраняются.
HTTP status успешного ответа SDK не предоставляет; 200 не выдумывается.

Причины хранятся в существующей диагностике Reply. История не мигрирует; запрос
last_search ограничен пользователем. По запросу причины Python возвращает только
подтверждённое резюме, после повторного открытия SQLite тоже. Старые сообщения без
подробностей дают «причина не установлена», а не объяснение про сеть/тариф/доступ.

## Ограничения и следующий шаг

Ни RequestEngine, ни нормы консолидации, ни схема БД, ни Windows supervisor не
менялись. Обычное представление не показывает произвольные source notes;
они сохраняются в оригинале/подробном виде. Город выводится из структурированного
атрибута, Python не угадывает его из заметок. Произвольный custom-текст генерирует
GPT, качество и естественная классификация намерений требуют живой приёмки.

Известные дефекты парсера устранены офлайн; работоспособность погодного запроса
в конкретном аккаунте/провайдере не подтверждена. Следующий шаг — review, затем
отдельно разрешённое развёртывание и один ручной тест. При повторном отказе новая
безопасная диагностика должна различить API/tool/source/parser этапы. Production
оставлен без изменений, main/merge/deployment в этом задании не выполнялись.
