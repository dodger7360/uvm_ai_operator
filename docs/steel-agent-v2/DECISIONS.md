# Решения пользователя

- Telegram — единственный текущий продукт; используется существующий UVM_Steel,
  второй бот не создаётся.
- GPT — главный интерпретатор, один чат без обязательных режимов. Python не
  дублирует предметное понимание модели.
- Исходные позиции, количества и коммерческие/технические отличия сохраняются.
- RAG, Bitrix24, Outlook, поставщики и остальные внешние интеграции заморожены.
- Разработка на Mac, эксплуатация и deployment на Windows.
- Production переключается только по прямому разрешению пользователя.
- Ненужные бюджетные и токенные ограничения API в v2 не вводятся; число повторов
  и длительность вызова ограничиваются для защиты от сбоев, а не экономии.
- Принцип критического обсуждения: технические риски и результаты испытаний
  важнее автоматического согласия; альтернативы обсуждаются явно.

№2 разрешает документацию, офлайн-аудит и исправление доказанных блокеров.
Он не разрешает paid API, запуск Telegram, deployment, commit, push или merge.
Это позднее решение о v2 не является разрешением отключить защиту legacy production.

## Уточнения Промпта №3

- При отзыве доступа заявки и история сохраняются. Чтение, обработка и доставка
  заблокированы до повторного одобрения; после него тому же Telegram ID вновь
  доступен прежний контекст v2. Это утверждённое поведение, не открытый блокер.
- Отдельную систему управления отзывом/очисткой контекста сейчас не разрабатывать.
- Разрешены проверка, один коммит и push feature/steel-agent-v2 с Mac в GitHub.
  Windows, main, merge, deployment и платные API-вызовы в №3 запрещены.

## Промпт №5 — Windows-кандидат

- Для начальной Telegram-приёмки v2 явно gpt-6-luna/high, без изменения .env,
  глобального env и настроек legacy. Ограничения денег/токенов не вводятся.
- Разрешены один коммит и обычный push отдельной Windows-ветки кандидата.
- Production, запуск/остановка, deployment и живые API остаются запрещены.
