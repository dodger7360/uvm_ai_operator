# Решения владельца и границы утверждения

18.10.2026, этап №23. Сводная редакция для review владельца. GitHub хранит
утверждённые требования и фактическое состояние; чат и Codex сверяются с ними.
Новые формулировки и критерии приёмки требуют review: публикация не равна утверждению.
Позднее явное решение владельца отменяет противоречащее историческое.

## Утверждено владельцем

- Цель — ИИ-оператор снабжения металлопрокатом с цепочкой из [PRODUCT.md](PRODUCT.md),
  а не только форматирование. Источник: задание №23.
- Один существующий UVM_Steel, единственный ИИ-мозг Steel Agent v2, gpt-6-luna/high.
  Старые ИИ-нормализатор и intent router исключены из активного Telegram. Полезные
  парсеры, модули и базы сохраняются для выборочного переноса. Уточнение №19.
- GPT понимает номенклатуру, смысл, намерения и предлагает коммерческие группы.
  Python выполняет точные расчёты Decimal, валидацию, версии, хранение и безопасные
  операции. Второй AI pipeline и прежняя многоступенчатая предметная архитектура
  без отдельного решения не создаются.
- Исходник, позиции, количества и различия сохраняются. Характеристики нельзя
  выдумывать; коммерческая группа не означает техническую взаимозаменяемость.
- SQLite в текущем контуре, разработка через Git/GitHub. Основная рабочая среда
  разработки и выполнения сейчас Windows; admin/IT не требуются.
- **Steel Agent v2 развивается по стратегии forward-only. Откат на устаревший код
  не является поддерживаемым штатным сценарием. Сохранность данных, очереди и
  восстановление после аварий остаются обязательными.** Решение №19.
- Прежние supervisor/start/stop/ProcessLock/Task Scheduler Action; один polling,
  до трёх execution worker, FIFO пользователя, durable inbox/attempt/outbox/cursor.
  Unknown GPT/Telegram не повторяются автоматически. Внешнего guard нет.
- При отзыве доступа данные сохраняются; чтение, обработка и доставка закрыты
  до повторного одобрения. Тот же аккаунт получает прежний контекст. Новая система
  ролей/очистки контекста не требуется. Решение №3 сохраняется.
- Искусственные денежные и токенные квоты не вводятся. Конечные повторы/таймауты
  служат устойчивости. Production/deployment и живые API требуют разрешения
  на соответствующий этап. Разрешение не переносится на самостоятельные новые работы.
- Production-заявки, переписку, payload и базы не переносить в GitHub. Новые
  примеры — синтетические либо явно разрешённые. Уточнение №21 действует далее.
- Целевой срок нормализации/диалога — максимум 14 дней от следующего этапа
  реализации; затем 12-недельный план №23. Это цели, не доказанное выполнение.
- Будущий складской Excel: `1.ОСТАТКИ`, J «В наличии т», N — город/филиал;
  B не заменяет город. Количество учитывать; применимость радиуса 400 км проверить.
  Bitrix24 в будущем — основной источник заявок и бизнес-истории, без копирования
  всех заявок в локальную SQLite. Источник: №23.
- Риски обсуждаются прямо; при противоречиях не соглашаться формально и не менять
  требования молча. Один чат без обязательных пользовательских режимов сохраняется.

## Подтверждено кодом или испытаниями

Это факты, а не новые бизнес-правила. Свидетельства — [PROJECT_STATE.md](PROJECT_STATE.md).

- V2-only entrypoint: missing/legacy config завершают запуск, fallback нет.
- Queue schema=1, write-before-ack, атомарные snapshot/version/history/outbox,
  recovery и no-replay unknown проверены офлайн; очередь развёрнута в №20.
- №21 подтверждает перекрытие API-вызовов двух пользователей. Три одновременно
  и ожидание четвёртого проверены офлайн; качество извлечения этим не доказывается.
- Простые create/edit/undo и диалог проходили живой Telegram. Структурные отказы,
  неполные характеристики и неудобный вывод остаются. Append отсутствует.
- Typing восстановлен №21, развёрнут №22; живая видимость ожидает подтверждения.

## Открытые вопросы

| Вопрос | На какое решение влияет |
|---|---|
| Существенные характеристики видов; когда нужны ГОСТ, длина, раскрой, исполнение | Уточнения и приёмка; универсальной обязательности не устанавливаем |
| Когда предлагать типовой вариант, когда только спрашивать | Разделение предположений и подтверждённых требований |
| Критерий готовности заявки | Право сообщать о полноте и передавать в закупку |
| Дубли и коммерческие группы | Суммирование с сохранением индивидуальных различий |
| Аналоги и допустимые замены | Статус соответствия и подтверждение сотрудником |
| Источники теоретической массы, пересчёты единиц | Получение тонн из метров/штук с доказательством метода |
| Несколько активных заявок пользователя | Выбор контекста, адресность правок, undo и append |
| Границы свободного диалога | Обсуждение, уточнение или операция без скрытой мутации |
| Ранжирование цен/поставщиков | Закупочные приоритеты, которые нельзя назначать самостоятельно |
| Подтверждение наличия и свежести цены | Срок доверия данным и учёт запрошенного количества |
| Филиалы, расстояние и радиус 400 км | Географический отбор, а не автоматический жёсткий фильтр |
| Форматы, права и ограничения Bitrix24 | Доступ к истории без полной локальной репликации |
| Интерфейсы/владение/актуальность существующих парсеров | Выборочный перенос, ограничения сайтов и обновление данных |

Ответы сейчас не запрашиваются. Неутверждённое бизнес-правило агент не устанавливает сам.

## Исторические и отменённые решения

Исторические отчёты сохраняются; доступность номеров перечислена в
[№23](reports/023-product-foundation.md). Mac был средой ранних работ, теперь
не обязательное условие. Default legacy, возврат старого SHA, rollback gate,
retirement/DROP, внешний guard с ProgramData/ACL/admin и сменой Action из №15–18
отменены №19. Их эксплуатационные процедуры не применять. Старые AIService и
предметные схемы корневых ADR не задают активную архитектуру v2.

Заморозка всех будущих интеграций заменена дорожной картой №23; их подключение
требует отдельной задачи. Ограничения commit/push старых этапов остаются историей
этих этапов, а не вечным запретом новых разрешённых публикаций.
