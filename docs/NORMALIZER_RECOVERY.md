# Паспорт восстановления нормализатора UVM_Steel

Дата фиксации: 2026-10-16. Этап B1: документация и воспроизведение,
без исправления бизнес-логики и без изменения действующего бота.

## Цель

Интеллектуальная нормализация больших заявок на металлопрокат: извлечение
всех исходных потребностей, объединение совместимых позиций, точное
суммирование, сохранение исходных характеристик и естественные команды
редактирования. Сохранение количества строк само по себе не доказывает
сохранение потребности. Коммерческая группировка не означает нормативную
взаимозаменяемость. Неизвестные характеристики нельзя додумывать.

## Воспроизведение B1

Тест: `tests/test_normalizer_recovery_b1.py`.
Вход — четыре строки из задания B1, без единиц, с точными исходными
фрагментами. Контролируемый ответ содержит четыре beam, С355-5,
типоразмеры и Decimal-количества, unit=None. Префикс ГОСТ к сокращённым
номерам не придумывается; номера сохраняются в исходном тексте.

Подменяется только `_invoke`: настоящий AIService.parse_request выполняет
проверку фрагментов. TelegramService работает с reliable=True и
commercial_view=True; используются настоящий TelegramRepository и временная
SQLite. Наблюдающая обёртка exact_source_attributes вызывает оригинальную
функцию без изменения результата. Сеть, SDK-клиент и production .env не используются.

Результат Windows: **1 failed** — ожидаемый воспроизводимый отказ приёмки.
Первый запуск в ограниченной среде не дошёл до сценария из-за прав на
временный каталог pytest; успешный запуск тестового контура выполнен с
отдельным временным каталогом вне репозитория. Полный pytest не запускался.

| Профиль | До exact_source_attributes | После | После «тонны» |
| --- | --- | --- | --- |
| 20Ш2 | 10.700 | None | quantity=None, unit=None |
| 30Ш2 | 186.698 | None | quantity=None, unit=None |
| 40Ш2 | 127.097 | None | quantity=None, unit=None |
| 45Ш2 | 56.669 | None | quantity=None, unit=None |

Сервис сохраняет четыре позиции и их полные source_text, но первый вывод
содержит только профили и марку без количеств. Затем спрашивает единицу
первой исходной позиции. После «тонны» повторяет тот же вопрос. Вызов
контролируемого извлечения один; дополнительных AI-вызовов нет.
381,164 т конвейером не получено. Первая доказанная потеря — присваивание
quantity=None в exact_source_attributes, до normalize_request и validate_request.

Тест намеренно красный, без xfail/skip и без закрепления дефекта как нормы.
Он содержит требования ко всему диалогу, включая все четыре единицы и сумму;
последующие проверки станут достижимы после устранения первой потери.
Он не доказывает качество живого GPT и отдельно не проверяет распознавание
сокращённых нормативных обозначений.

## Порядок ремонта после отдельного согласования

1. Количество и единицы: сохранять явно извлечённое число при неизвестной
   единице; проверить маршрутизацию «тонны» и область общего уточнения.
2. Извлечение и fallback: сохранять непроверенный ответ для адресной проверки,
   поддержать балки в существующем распознавателе, завершать partial после
   проверки исправлений. Не отключать защиту от вымышленных характеристик.
3. Контекст: локальные команды нормализации/показа/общей массы, понятная
   обработка коротких ответов без потери активной заявки.
4. Групповые правки: естественный порядок слов и проверяемая область изменения;
   согласовать техническое обозначение и коммерческую подпись.
5. Полные закупочные эталоны: исходные характеристики, связи, арифметика,
   порядок и формат; затем отдельная разрешённая Telegram-приёмка.

B1 не исправляет перечисленные механизмы. Первый следующий шаг — минимальное
исправление потери количества с неизвестной единицей, после согласования.

### Реальный исходник B2.1

Рабочая основа B2.1 — B2, отдельная ветка
`feature/normalizer-recovery-b2-real-input`. Тест
`tests/test_normalizer_recovery_b2_real_input.py` использует именно:

```text
Балка 45Ш2 12 000 С355-5 Р 57837-2017 56,669

Балка 30Ш2 12 000 С355-5 35087-2024 186,698

Балка 40Ш2 12 000 С355-5 Р 57837-2017 127,097

Балка 20Ш2 12 000 С355-5 35087-2024 10,700
```

Ни тире, ни другие разделители в SOURCE и source_text не добавляются.
Тест проверяет, что AIService получил ровно SOURCE. Реальные parse_request,
проверки фрагментов, coverage, normalizer, validator, маршрутизация и временная
SQLite сохранены; подменяется только транспорт модели.

Первый запуск на B2: **1 failed, 9 passed**. Четыре позиции сохранялись,
но количества были None: правило B2 требовало разделитель перед числом.
Поэтому зелёный B1 не доказывал работу исходного экспорта.

Минимальное исправление — `quantity.beam_export_columns`: полное совпадение
формата «балка, профиль, исходная длина, класс стали, нормативное обозначение,
конечное десятичное количество». Без совпадения всех колонок это правило
не применяется. Извлечённое моделью количество должно точно совпадать
с конечным числом; длина, год, номер документа, марка и профиль не подходят.
Два числовых окончания, альтернативы и целочисленное окончание без
подтверждённой роли отвергаются. Это не универсальный разбор всех таблиц.

`exact_source_attributes` сохраняет буквальное требование длины `12 000`,
даже если модель его пропустила. Значение в миллиметрах не добавляется:
существующий `_normalize_length` требует явную единицу, а проверенное
`length_mass_columns` относится только к экспорту уголков/швеллеров с кг.
Предположение модели length_mm=12000 для этих балок не проходит валидацию
как подтверждённая длина. Отдельный отрицательный тест сохраняет эту защиту.

После исправления на неизменённых строках: четыре исходные позиции,
С355-5 без замены, количества 56.669 / 186.698 / 127.097 / 10.700,
сначала unit=None, после «тонны» все unit=т, сумма **381.164 т**.
Исходный порядок закреплён source_position, item_id уникальны, source_text
и original.source_text полные. Вывод сортируется существующим formatter.
Повторного вопроса об общей единице нет; транспорт извлечения вызван один раз.

Нормативные обозначения `Р 57837-2017` и `35087-2024` остаются в полных
исходных фрагментах, без добавления префикса ГОСТ. В этом тесте gost_tu=None:
их структурированное нормативное распознавание и показ в коротком перечне
не реализуются этим исправлением. Длина сохраняется как raw requirement,
но её единица остаётся неподтверждённой. Это оставшиеся ограничения,
а не доказанная полная техническая нормализация балок.

Полный pytest, живой GPT и Telegram не запускались. Production не изменялся.
Профильный набор B1/B2/B2.1, экспортные строки, уточнения, проверки источника

## B3 — сохранение проверенной части отклонённого извлечения

Дата: 2026-10-16. Основа: `a27b86c568c274f8fe0a3a0c2dd6faa9af055812`,
ветка `feature/normalizer-recovery-b3`, отдельный worktree. Production не менялся.

На исходной версии воспроизведено: три точных фрагмента реальных балок
и один изменённый фрагмент дают `source_fragment_mismatch`; recovery получает
ноль извлечённых позиций, локальный распознаватель балки не поддерживает,
итог — original, 0 items, 4 необработанные строки. Начальный набор B3:
7 failed, 2 passed. Подменён только транспорт; AIService.parse_request,
проверки источника и TelegramService настоящие, SQLite временная.

Минимальная передача данных:

- AIService.parse_request сохраняет глубокую копию отклонённого structured
  response в атрибуте исключения SemanticExtractionError. Метод по-прежнему
  выбрасывает ошибку, не возвращает успешную заявку и не пишет ответ в журнал.
- TelegramService._build_active в reliable-режиме передаёт этот payload
  существующему capture_extraction и повторно выбрасывает исключение.
- _recover проверяет кандидатов отдельно через тот же _build_active.
  Проверяются source coverage, марка, стандарты, количество и характеристики.
  Предупреждение о неподтверждённых данных или потеря заявленного количества
  не допускают переноса кандидата в проверенную часть.
- Для требуемого строкового типоразмера, дополнительных числовых размеров,
  формы и обработки добавлены консервативные проверки существующими
  предикатами validator. Отдельные красные тесты подтвердили, что без этого
  recovery пропускал вымышленный профиль, обработку и необязательный размер.
  Общий валидатор и правила нормализации/консолидации не изменены.
- Проверенный кандидат потребляется один раз; конфликтующие варианты одной
  строки не выбираются произвольно. Каждая исходная строка рассматривается
  отдельно. Неподтверждённая строка остаётся в unprocessed_source, либо может
  быть независимо восстановлена существующим локальным распознавателем.

Отклонённый ответ существует только в памяти текущей операции: существующий
ContextVar сбрасывается в finally. В итоговый ActiveRequest не переносится
initial_extraction отклонённого ответа; в SQLite попадают исходник и повторно
проверенная часть. Тест проверяет отсутствие изменённого моделью фрагмента
в telegram_history и отсутствие исходных строк/отклонённого текста в логах.

Приёмка:

| Сценарий | Результат |
| --- | --- |
| 3 точных фрагмента + 1 ошибочный | 3 позиции с точными Decimal, С355-5 и raw длиной; 1 необработанная исходная строка; partial, is_valid=false; полный оригинал показан |
| Все 4 фрагмента корректны | Обычный путь без fallback; «тонны» даёт 381,164 т |
| Вымышленная дополнительная позиция | Не включается; четыре реальные позиции проверены; результат остаётся partial |

| Конфликтующие варианты одного фрагмента | Эта строка не принимается; остальные сохраняются |
| Выдуманный ГОСТ, количество, профиль, обработка, размер или неподтверждённая длина | Повреждённый кандидат не принимается как проверенный |
