## Границы подтверждения

Публикация рабочей ветки не является разрешением обновить main или production.
Сначала пользователь рассматривает PR и подтверждает обновление main.
Production-процессы, база, конфигурация и автоматические задания до этого
подтверждения не изменяются.

Реальный polling и ответы Telegram этим локальным прогоном не проверены.
Платные OpenAI/Web Search smoke-тесты требуют отдельного подтверждения.
Нельзя объявлять deployment успешным только по pytest или наличию PID.

## Последующий deployment и откат

После подтверждения main:

1. Определить фактический production HEAD, процессы, runtime-путь SQLite,
   доступность .venv и настройки без вывода секретов.
2. Сохранить предыдущий HEAD. Создать согласованную SQLite-копию через backup
   API вне репозитория, проверить integrity_check, сохранить конфигурацию и
   необходимые локальные файлы только локально. Не публиковать их содержимое.
3. Использовать существующий `stop-telegram.ps1`: maintenance-маркер завершает
   текущую обработку и останавливает worker/supervisor. При тайм-ауте ждать и
   проверять; не убивать заявку и не запускать второго worker.
4. При чистом production и возможности fast-forward обновить только до
   подтверждённого SHA main. Базу, .env и сеть не подменять.
5. Один запуск через `start-telegram.ps1`. Проверить ready, фактический PID,
   единственность polling, свежие безопасные логи, SQLite и права пользователей.
6. Реальные заявки/рабочие вопросы/поиск запускать только после разрешения
   на соответствующие платные тесты.

При сбое сначала остановить новый экземпляр штатным maintenance-механизмом и
подтвердить завершение. При чистом дереве вернуть код через
`git switch --detach PREVIOUS_HEAD` без reset --hard и без переписывания истории,
затем выполнить один штатный запуск. Сохранить актуальную SQLite: откат кода
не является разрешением восстановить БД из backup. При неопределённом состоянии
процессов/данных дальнейшие действия остановить и сообщить оператору.

После запуска подготовить локальные результаты реальных испытаний вне Git:
test_id, время, SHA, исходный текст, результат, уточнения, ожидаемый результат,
отклонение и класс ошибки. Эти данные не отправляются во внешние системы
автоматически; будущие публичные регрессии формируются только после обезличивания
и отдельной проверки. Путь локальной диагностики определяется при этапе E.
