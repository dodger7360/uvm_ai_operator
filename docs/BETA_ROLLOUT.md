# Обновление действующего бета-бота

Бот остаётся на Windows. Отдельный тестовый бот не нужен. Mac используется
для разработки и прямой приёмки API без Telegram polling. Bitrix не подключается.
Пользователь разрешил интеграцию после проверок; устаревшее требование отдельного
тестового бота в документации первого этапа заменено этим решением.

## Что ограничивается

`run_bot` всегда подключает один BetaBudget к извлечению, классификации,
семантическим повторам и WorkAssistant. SQLite `ai-budget.sqlite3` лежит рядом с
фактическим `OPERATOR_DB` (по умолчанию в каталоге бота). Его нельзя удалять,
заменять пустым, копировать из dev или автоматически обнулять при перезапуске.
Участники по-прежнему проходят существующую проверку прав; новых прав код не выдаёт.

- 60 вызовов на весь этап; резерв 5 центов за каждый вызов, всего $3.
- 20 вызовов на пользователя за этап; 10 за скользящие сутки, 6 за час.
- 18 общих вызовов в час; 3 вызова в одном сообщении, включая классификацию/повторы.
- Только `gpt-6-luna`, Standard (`service_tier=default`), без платных tools.
- Не более 48 000 UTF-8 байт совокупного содержимого запроса (включая инструкции,
  историю и схему структурированного ответа), без скрытого обрезания.
- Вывод нормализатора ограничен 24 000 токенами, включая reasoning;
  обычного помощника — прежними 2 500 токенами.
- SDK retries=0; таймаут нормализатора 180 секунд, помощника 60 секунд.
- Каждая попытка атомарно резервируется ДО сети, в том числе семантический повтор.
  Ошибки/таймауты и отсутствие usage не возвращают резерв: списание у провайдера
  при обрыве неизвестно. Ошибка/блокировка журнала закрывает платный путь.

Это консервативный бюджет попыток, НЕ баланс кошелька и НЕ ограничение других
приложений с этим API-ключом. При подтверждённых 15 октября 2026 Standard-тарифах
Luna ($0.10/1M вход, $0.50/1M выход) указанные текстовые ограничения укладываются
в резерв с запасом. Учёт usage и estimated_usd в диагностике остаётся оценкой;
неизвестное usage не считается нулевым. Перед изменением модели/тарифа или выдачей
новой квоты требуется отдельная проверка. Endpoint должен быть прямым OpenAI API;
нестандартный OPENAI_BASE_URL блокируется и в Telegram, и при живой приёмке.

Платный web_search временно блокируется. Локальный расчёт, просмотр и правки,
которые не требуют AI, работают после исчерпания квоты. При лимите AI не подменяет
текущую заявку локальным fallback новой заявки: сообщает об ограничении и просит
сохранить новый текст. В служебных логах — reason, reservation ID, резерв и usage;
нет исходных сообщений, Telegram ID, ключей и URL с секретами. Сам журнал квот
хранит ID для применения индивидуальных лимитов и остаётся локальным, как SQLite.

## Приёмка на Mac

Офлайн: существующее окружение Python, полный pytest с временными БД.
Четыре legacy_23met исключаются настройками проекта. Один оставшийся тест требует
локальных HTML-снимков `tmp/23met_research/armatura_{a1,a3,at800}_12.html`.
Для этой проверки они взяты из существующей папки проекта без изменения оригиналов;
снимки не публикуются в Git. Без них этот тест падает из-за отсутствия fixture.

Живой запуск только явной командой из корня репозитория:

```text
python scripts/beta_acceptance.py --live --env <существующий .env> --ledger <постоянный путь acceptance.sqlite3> --report <report.json>
```

Скрипт использует исключительно синтетические строки, не импортирует Telegram,
не открывает рабочую БД, не запускает polling. Проверяет 40→40, 40→20, 40→15,
100→15, смешанные кг/т, полноту source_indices и точные суммы. При первом сбое
останавливается; по умолчанию шесть попыток с резервом $0.30 за весь срок журнала.
Явное расширение `--call-limit 8 --resume --reasoning medium` допускает максимум
восемь попыток с резервом $0.40 и часовым лимитом приёмки восемь. Квоты Windows
не меняются: вместе это максимум $3.40, ниже заявленных примерно $4.
Повторный запуск использует тот же журнал и отчёт приёмки; ошибки сохраняются.

Источники лимитов API и тарифов:
https://developers.openai.com/api/docs/models/gpt-6-luna
https://developers.openai.com/api/docs/guides/token-counting

## Windows: предварительная проверка и установка

Исторически подтверждён каталог `C:\Users\usoshin\uvm_ai_operator`, supervisor,
worker и `start-telegram.ps1` / `stop-telegram.ps1`. Последний отчёт чата
«Работа ПК Винда» сообщает успешное обновление до `defeae61`; это не текущая
проверка машины. Перед установкой Windows-исполнитель обязан заново проверить:

1. Фактический каталог, HEAD, чистоту tracked-файлов и актуальный GitHub main.
   Не применять reset --hard / clean и не перезаписывать незнакомые изменения.
2. Реальные PID и время запуска supervisor/worker; ровно один polling.
   Не выводить аргументы с секретами. Не менять Task Scheduler.
3. Настоящий путь OPERATOR_DB, модель `gpt-6-luna`, прямой endpoint OpenAI
   (включая возможный OPENAI_BASE_URL), существующую сеть/прокси; не менять .env.
4. `integrity_check=ok`, схему, количества и контрольные суммы прежних таблиц:
   права, активные заявки, история, offset. Только метаданные, не тексты.
5. Проверенные резервные копии SQLite через `sqlite3.Connection.backup` и
   существующего журнала квот (если есть), исходный SHA и инструкции отката.
   Первый запуск новой квоты допустим только если журнал ещё не создавался.

Далее штатный `stop-telegram.ps1`: maintenance marker остаётся на месте.
Дождаться завершения обработки и выхода ОБОИХ процессов, проверить отсутствие
polling. При таймауте не убивать процесс и не стартовать второй. После остановки
сделать окончательный согласованный backup и повторить метаданные базы.

Обновить main только fast-forward до проверенного SHA. Проверить импорты,
зависимости и тесты в отдельной папке с временными базами. На backup проверить
создание двух таблиц normalization_rule/normalization_rule_event, чтение прежних
JSON и неизменность прежних данных. Журнал квот — отдельная БД, не новая таблица
в рабочей SQLite. До возобновления сохранить baseline для сравнения.

Запустить ОДИН раз штатным `start-telegram.ps1`; убедиться в одном supervisor,
одном worker, подключённом polling, отсутствии 409/import/auth/SQLite ошибок.
Наблюдать не менее трёх минут. Сравнить целостность, права и прежние записи
с baseline; новые пользовательские записи нельзя считать повреждением.
Не отправлять сообщения участникам для проверки без отдельного поручения.

При сбое штатно остановить новый код, сохранить текущие БД/журналы, вернуть
предыдущую версию кода безопасным способом и запустить один экземпляр.
Не восстанавливать старую SQLite автоматически из-за ошибки кода: это теряет
новые заявки/историю. Аддитивные таблицы можно оставить. Для отката на версию
без лимитов сначала закрыть платную обработку или согласовать риск расхода;
бесконтрольный рестарт старого AI-пути не является безопасным откатом.

После успешной установки пользователь проверяет в своём Telegram групповые
правки, восстановление, реальные дубли и большие заявки; сверяет источник и суммы.
Утверждение/отзыв глобальных правил проверено офлайн, Telegram UI для этого пока нет.
