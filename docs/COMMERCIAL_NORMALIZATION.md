# Коммерческое представление заявки

Коммерческая консолидация — режим существующего `consolidate_items`, а не
второй нормализатор. Исходные `ActiveItem`, их `original`, `source_text`, марки,
ГОСТ, количество и единицы не переписываются. Итоговые группы содержат копии
всех участников (`source_items`), исходные индексы, позиции и стабильные ID.
Количество суммируется через существующую точную арифметику Decimal; проверяются
однократное покрытие источников и сохранение суммарного количества по единицам.

## Общие правила

- Ст3 без раскисления либо с пс/сп, в том числе с категорией и группой В,
  и С255 с индексами образуют коммерческую группу `ст3`.
- С345/С355 образуют отдельную группу. Разные категории только С345 отображаются
  как С345; участие С355 даёт С355. Одинаковый конкретный класс с индексом
  сохраняется. Исходные категории остаются на участниках.
- 09Г2С не входит в группу С345/С355. Префикс «Ст» перед 09Г2С убирается
  только в коммерческой подписи; исходное обозначение сохраняется.
- Ст3кп и альтернативные перечни марок не включаются в коммерческие группы
  автоматически.

Совместимость требует одинаковых структурированных размеров, серии,
исполнения, обработки, покрытия, требований к длине/стенке и единиц после
штатной нормализации. Непредставленные признаки исходного текста блокируют
автоматическое объединение. Известные полные названия горячекатаных равнополочных
уголков и горячекатаных швеллеров считаются вариантами их наименования.

Сортаментные и другие документы являются точными ограничениями. ГОСТ 535 и
ГОСТ 27772 могут различаться между участниками согласованной коммерческой
группы стали. Если один номер документа присутствует с разными редакциями,
автоматического объединения нет. Другие ГОСТ/ТУ/СТО не подменяются. Коммерческая
строка показывает документы одного исходного представителя; полный набор
каждого участника сохраняется в `source_items` и исходной заявке. Это не
утверждение нормативной эквивалентности или технической взаимозаменяемости.

## Явные решения одной операции

`approve_group` принимает заявку, выбранные исходные ID, подпись, ID
представителя и основание. `CommercialDecision` привязан к ID заявки и
отпечатку её технических данных. Номера строк, размеры, контрольные массы,
имена fixture и количество товаров не являются runtime-триггерами.

Один источник нельзя включить в два решения. Размеры, серии, структурированное
исполнение и единицы должны совпадать даже при явном решении. Непредставленные
исходные признаки требуют отдельного `allow_unmapped_source=True`. После
изменения исходных данных решение перестаёт применяться; требуется новое
согласование. Решение другой заявки отклоняется.

Согласованный эталон 38 → 28 требует двух явных решений: для исходных участников
коммерческого уголка 50х50х5 (включая обозначение Б и ГОСТ 535-05) и для пары
швеллеров 20У 09Г2С/С345-6. Документы представителя последней группы —
ГОСТ 27772-88 и ГОСТ 8240-97. Без решений общий алгоритм оставляет 30 строк.
Эталон и выбор участников находятся только в тестах; автоматической runtime-
регистрации исключения нет.

## Интеграция и совместимость

Штатная точка создания TelegramService включает коммерческий режим для новых
заявок. Старый JSON без поля `commercial_view` читается в прежнем техническом
режиме; SQLite не мигрируется. Python-клиенты сохраняют прежнее поведение
двухаргументного конструктора и могут явно выбрать `commercial_view=True`.
Форматирование и выбор участников при корректировках используют один общий
`request_consolidation`.

Для локальной операции решения передаются явно через
`process(..., commercial_decisions=callback)`. Callback получает уже проверенную
заявку и возвращает решения `approve_group`. Они сохраняются в её существующем
JSON и восстанавливаются после загрузки. Это доверенный прикладной интерфейс;
новая Telegram-команда согласования на этом этапе не добавляется. GPT не
формирует и не утверждает CommercialDecision; AI-схемы и промпты не меняются.

Обычный коммерческий вывод группируется по виду и материалу, без заголовков,
с пустыми строками между блоками. Тонны показываются с тремя десятичными знаками
и запятой; точная сумма не округляется в данных. Коммерческая подпись не служит
основанием расчёта плотности: существующее допущение массы листов действует
только при подтверждённой применимости к каждому исходному участнику.
