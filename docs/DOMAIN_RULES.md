# Правила нормализации заявок

Актуализировано 14.10.2026: автоматическая консолидация производного
представления. Исходные позиции сохраняются; технические замены запрещены.

## Первичная нормализация

AIService извлекает отдельную структурированную позицию для каждого исходного
фрагмента. Python проверяет исходные фрагменты, сохраняет количество как Decimal,
восстанавливает полные известные обозначения сталей и все написанные ГОСТ/ТУ/СТО
из исходного текста, нормализует оформление и валидирует данные.

Запрещены автоматические замены марок, классов, категорий и стандартов.
С245, С255, С255-4, С345-6, С355-6, 345-9-09Г2С, 09Г2С-12, Ст3пс5,
Ст3сп5 и ВСт3сп5 сохраняются. ГС не раскрывается автоматически в 09Г2С.
Отсутствующие марки, стандарты, длины, покрытия и раскрой не дополняются.
При первичной нормализации полностью идентичные закупочные позиции
автоматически консолидируются в итоговом представлении с суммированием количеств.
Все исходные позиции и количества сохраняются. AI извлекает дубликаты отдельно;
проверка полноты выполняется до построения представления. Каждая исходная
позиция принадлежит ровно одной группе. Дополнительной команды или согласия
для идентичных позиций не требуется.

## Единицы и числа

Telegram поддерживает т, кг, шт., м, пог. м, м². Исходная единица сохраняется.
В итоговом представлении кг автоматически переводятся в т: 1000 кг = 1 т.
quantity.py — единственная реализация точного перевода; текущие исходные
quantity/unit и первоначальные original не переписываются. Шт. суммируются
только со шт., м — с м (пог. м — совместимый алиас); другие размерности не
смешиваются. Исходные шт./м не переписываются в тонны. Для обычного сплошного листа Ст3
добавляется отдельная расчётная оценка массы по описанному ниже допущению;
для других категорий перевода по неподтверждённой массе нет.
Количество хранится как Decimal и сериализуется строкой, без округления. 33,600 → 33,6; 0,0015 → 0,0015.
Procurement/inventory продолжают использовать масштабированный SQLite INTEGER
с прежними ограничениями точности и диапазона. Их to_scaled_quantity использует
тот же normalize_quantity. Активная Telegram-заявка хранит Decimal JSON-строками:
точность не обрезается до inventory-масштаба. Суммы строятся точно; округляется
только итоговое отображение по существующей настройке.

## Формат и порядок

Одна позиция — одна строка, без нумерации, приветствий, заголовков и разметки.
Размеры используют ×, диаметры Ø, десятичные дроби запятую.
Сохраняются разновидности труб и листов, составные обозначения ленты,
ГОСТы, ТУ, СТО, требования к длине и стенке, форма поставки.
Порядок групп: круглые трубы, профильные трубы, листы, ПВЛ, балки, двутавры,
уголки, швеллеры, арматура, круги, полосы, прутки, проволока, лента, сетка,
соединительные элементы. Внутри группы числовая сортировка по типоразмеру.
Листы сортируются по фактической толщине независимо от Х/К и Г/К.
Равные ключи сохраняют исходный порядок. Неизвестные группы идут последними.
Вопросы отправляются отдельно от текста перечня. При отсутствии количества
позиция сохраняется и бот просит уточнение.

## Корректировки

AIService различает новый перечень, правку и неоднозначную команду.
Правка представляет список item_id / field / value / restore, а не
повторную генерацию позиций. MVP разрешает grade, quantity, unit.
Остальные изменения требуют уточнения и пока не поддерживаются.
Обычный номер относится к текущей итоговой строке. Если у неё несколько
источников, сначала выбирается конкретная исходная позиция; количество группы
не распределяется между ними произвольно. Команда «В исходной позиции 2 измени
количество на 500 кг» относится к второй строке первоначального входного перечня.
Для старого JSON без source_position используется прежний порядок сохранённых
items; после обновления он не переобозначается задним числом.
Восстановление берёт значение из original данной позиции.
Проверка правок выполняется на копии; при ошибке вся правка отклоняется.
После правки возвращается весь перечень. Новая заявка заменяет активную,
не наследует прежние замены; история сохраняется.

## Ограничения

AI не является источником технических фактов. Проверка известных обозначений
не заменяет экспертизу произвольной номенклатуры. Марки иных семейств остаются
под контролем извлечения и валидатора. Пропущенные строки с распознаваемым
товарным названием и числом блокируют сохранение новой заявки; это не
универсальный доказанный контроль всех возможных видов таблиц.
Поддерживается текст, включая табуляцию и многострочные фрагменты. Вложения
не разбираются. Части заявки, отправленные разными Telegram-сообщениями,
не склеиваются автоматически. Ответы разбиваются между позициями, одна строка
свыше 4000 единиц UTF-16 требует сокращения.


По отдельной команде оформления тоннажа («тоннаж приведи к виду 0,100т,
три знака после запятой») активная заявка сохраняет tonnage_decimals=3
(также поддерживается 2). Отображение округляется ROUND_HALF_UP, нули
сохраняются, перед т пробела нет. Пример: 0,0015 → 0,002т.
Исходное и текущее количество Decimal не изменяются. Другие единицы
не затрагиваются. Настройка сохраняется при правках этой заявки;
новая заявка начинает с точного формата без округления. При формулировке
«три знака, либо два» выбирается первый указанный вариант — три.


Общие шапки листов: каждый блок «лист ГК ГОСТ 19903 Ст.09г2с раскрой 1,5*6м:»
с последующими строками «толщина — количество единица» разворачивается перед
AI-разбором, только если вся область применения однозначна. Явный раскрой в
метрах переводится в миллиметры (1500×6000), тип, марка и ГОСТ переносятся в
каждую позицию. Следующая шапка или самостоятельная товарная строка завершает блок;
пустые строки не создают позиций. Раскрой без единиц этим правилом не
интерпретируется. Нераспознанная числовая строка внутри подтверждённого блока
останавливает обработку, а не исчезает из результата. Полный исходный текст хранится в ActiveRequest.source_text;
в ActiveItem.source_text остаётся исходная строка, source_context хранит шапку.
Отдельные марки стали не заменяются: Ст.09г2с оформляется как Ст09Г2С.


## Альтернативы и уточнения — 13.10.2026

«Ст3 (или Ст20)» — одна товарная позиция с двумя разрешёнными альтернативами,
а не неоднозначность, требующая удаления одной марки. Обе марки сохраняются
при первичной нормализации. Две марки без указания отношения требуют вопроса.
ГОСТ не включает разделительный дефис перед количеством. Круглая труба с
явным ГОСТ 10704 отображается как «Труба э/с», без добавления нового стандарта.
Запрет автоматических замен С245/С255/С255-4/С345-6/С355-6 остаётся действующим.
Короткий ответ применяется только к сохранённому вопросу конкретной позиции.
«Да» не означает согласие на произвольную замену; подтверждается только
зафиксированное предложение. Новая полноценная заявка заменяет старый контекст.


## Сохранение исходных позиций и короткий типоразмер уголка

Проверка полноты использует то же сопоставление исходных фрагментов, что AIService:
регистр, пробелы и пунктуация не меняют границы токенов. Например, `530*10` и
`530×10` могут обозначать одну исходную строку; перед восстановлением марки,
ГОСТ/ТУ и Decimal количества возвращается буквальная исходная строка. Число
вхождений обязательно: два одинаковых товара требуют двух отдельных items.
Развёрнутая строка листа сопоставляется со своей исходной строкой и своей шапкой;
характеристики не переносятся в следующую группу. Шапки не являются items.

`Угол 25*3 ... ГОСТ 8509` — сокращённый размер равнополочного уголка: сторона
25 мм, толщина 3 мм; обе стороны равны согласно явно указанному стандарту.
В выводе сохраняется `25×3`, ГОСТ не дополняется годом. Без явного ГОСТ 8509
вторая сторона не достраивается. Основание: [Росстандарт, ГОСТ 8509-93](https://protect.gost.ru/gost/details/c12253e4-5eaa-4175-a644-9ee4b3c1c948).
У ПВЛ размер `508*450мм` оформляется как `508×450`; значения не пересчитываются.

Изменение С245/С255/С255-4/С345-6/С355-6 возможно лишь отдельной явной командой
после первоначального разбора. Локальная глобальная правка сопоставляет полную
марку: С255 не совпадает с С255-4 и не заменяет часть альтернативной марки.


## Ожидающие операции — этап 1, 13.10.2026

Уточняющий вопрос сохраняется перед отправкой ответа. Простые вопросы о
количестве и единице используют PendingClarification; другие вопросы и
предложения правок используют PendingOperation в JSON активной заявки.
Состояние операции хранит пользователя, request_id, operation_id, отпечаток
текущих позиций, исходную команду, вопрос, накопленные ответы и точные edits,
если требуется подтверждение. Таблицы SQLite не меняются.

«Да» применяет только сохранённые конкретные правки; если данные ещё не
определены, бот повторяет вопрос и просит конкретный ответ. «Нет», «отмена»
и /cancel отменяют ожидающее действие без изменения заявки. Отменённый
вопрос не восстанавливается автоматически на следующем «Да». Новая заявка
заменяет старое ожидание; устаревшее предложение нельзя применить к другой
или изменённой заявке. Успешное выполнение и очистка ожидания сохраняются
одной транзакцией с историей; при ошибке ожидание остаётся для повторной
попытки или отмены. Это не гарантия exactly-once доставки Telegram.

Нормативный convert_units для шт./м и явная операция calculate_mass пока
не выполняются: подтверждённых весовых таблиц нет. Это не блокирует отдельную
автоматическую оценку сплошного листа Ст3 по расчётному допущению ниже. merge_items возвращает уже автоматически
построенное представление и не удаляет items/не применяет вложенные правки.
Неподдерживаемый запрос не создаёт фиктивного подтверждения и не поглощает
другое ожидание. Формат округления тоннажа остался прежним.


## Исходные позиции и производные группы

Исходный текст сохраняется дословно. Нормализованные исходные items содержат
оформленные характеристики, своё текущее количество/единицу, original и
стабильный item_id; новые заявки также имеют source_position входной строки.
consolidation.py строит отдельные ConsolidatedGroup с производным RequestItem,
source_indices, source_positions и source_item_ids. Новые source_positions
определяются при сопоставлении с физическими исходными строками, а не по
порядку ответа AI; равные ключи сортировки сохраняют фактический порядок входа. Суммы не сохраняются поверх
исходных количеств. Форматтер использует общий порядок групп для Telegram и
Workbench. Повторное построение не складывает уже вычисленные суммы.

Ключ консолидации сравнивает все закупочные поля RequestItem, включая полную
марку/альтернативы, нормативы, геометрию, разновидность товара, форму, обработку,
тип и требования длины/стенки. Существующий Product identity v1 не меняется и
не служит единственным критерием. None не совпадает с известным значением.
Неполная геометрия, неподдерживаемая категория или неотражённые в полях слова
исходной строки/шапки блокируют объединение. Это консервативное ограничение:
некоторые одинаково написанные сложные строки могут остаться раздельными, пока
их существенные требования не представлены однозначно.

В Workbench исходные позиции доступны в current_request.items, исходные
нормализованные снимки — original_items, производные группы — вычисляемое
consolidated_groups. Правка исходной позиции немедленно обновляет группы;
отдельного хранилища и редактора не добавлено. Действующие проверки исходных
фрагментов и товарных строк выполняются до консолидации. Старые форматы только
с общей шапкой в Workbench сохраняют прежний путь обработки.

Ручные и подтверждённые правки Telegram меняют конкретный item_id и сохраняют
историю как прежде; ответ строится заново. Нет SQL-миграции и переписывания
существующих активных/исторических заявок. Новое поле source_position исключено
из отпечатка значимых данных, чтобы старые ожидающие операции не стали
устаревшими только из-за добавления метаданных.


## Автоматическая расчётная масса листа — 14.10.2026

Для обычного сплошного прямоугольного листа с полной геометрией и точной маркой
Ст3 при положительном целом количестве в шт. автоматически добавляется оценка:

`Лист 6×1500×6000 Ст3 — 4 шт. = 1,696 т`

Формула: `m_кг = (толщина_мм × ширина_мм × длина_мм / 10^9) × 7850 × количество_шт`.
Все произведения и преобразования массы выполняются через Decimal. Плотность
7850 кг/м³ — документированное расчётное допущение только для этой области
применимости; [основание и границы](METAL_REFERENCE.md#расчётное-допущение-для-листа-ст3).
Статус результата — `estimate`, не нормативная масса конкретного изделия.

Исходное количество — заявленные пользователем шт., кг, т и другие единицы.
Расчётная теоретическая масса — результат формулы по номинальной геометрии
и плотности, не взвешивание. Нормативная масса требует применимого проверенного
источника/нормативного варианта. Фактическая масса партии определяется измерением.
Знак `=` в интерфейсе обозначает расчётную эквивалентную массу, а не равенство
результату взвешивания. В примере: один лист 423,9 кг, четыре — 1695,6 кг
или 1,6956 т. Только отображение округляется ROUND_HALF_UP до трёх знаков,
с десятичной запятой и удалением незначащих конечных нулей.

В текущей позиции хранится Python-поле mass_calculation: статус/причина,
метод, ссылка на допущение, плотность, текущие входные количество/единица,
исходная единица, геометрия в мм, масса штуки, общая масса в кг и т.
Decimal сериализуется строкой. Поле исключено из схемы ответа AI, ключа
консолидации и отпечатка ожидающей операции. Старый JSON без поля читается;
SQL-миграций и изменения таблиц нет. original, source_text и исходные количества
не заменяются оценкой массы; существующие записи не переписываются при загрузке.

Расчёт использует quantity.py после проверки исходных позиций, общий для
Telegram и Workbench. Нормализация и проверка обновляют метаданные; перед
ответом/построением групп они пересчитываются из текущих фактов. Количество
в группе сначала суммируется точно в штуках, затем рассчитывается масса;
повторный вызов не складывает производные результаты. После правки количества,
единицы или марки старый результат пересчитывается либо становится unavailable.
При изменении геометрии в структурированной позиции и повторной нормализации
масса пересчитывается. Противоречие размеров в полях и обозначении отключает
оценку. Нового Telegram-редактора размеров не добавлено: текущие команды
корректировки по-прежнему ограничены grade/quantity/unit.

Для неполной геометрии/количества, дробных шт., других марок и материалов,
исполнений (ПВЛ, рифлёный, перфорированный, покрытый лист, рулон) масса не выводится.
Наличие слова «Ст3» не разрешает расчёт листа из алюминия или иного материала.
Для остальных категорий поле отсутствует/равно null; калькулятор возвращает
unavailable. Перевод кг → т остаётся прежним и не смешивается с оценкой шт. → масса.
Настройка отображения тоннажа не меняет правило трёх знаков для расчётной массы.
