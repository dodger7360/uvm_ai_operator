## Что реализовано и исправлено

1. Многострочные позиции в кавычках объединяются в логические исходные строки. Число физических строк не подменяет число товаров.
2. «Соединительный элемент» распознаётся как товар. Устранён источник ложного расхождения количества исходных и извлечённых строк в смешанной спецификации.
3. Массовое количество применяется через Decimal к исходным позициям или указанному диапазону. Конфликт заполненного количества либо единиц отклоняется атомарно, без частичного изменения и неявной конвертации.
4. Явная команда «Замени количество у всех позиций на 1 шт.» поддержана при ожидающем количественном уточнении. Команда без намерения замены не перезаписывает конфликтующие значения. Исходные данные остаются в original; сохранённые состояния — в telegram_history, ответы — в clarification_answers.
5. Повторяющиеся вопросы сгруппированы по исходным позициям; частичный ответ сохраняется, спрашиваются оставшиеся характеристики.
6. source_position для пользователя отделён от реального индекса items[index]. Проверены позиции 3/7 и совместимость старых состояний уточнений.
7. Размеры разбираются через Decimal и безопасно преобразуются в существующие поля float. Проверяются формат, положительность, конечность и сохранение точности. Ноль, отрицательное число, частично распознанная экспонента и исчезновение малого значения при конвертации не закрывают вопрос. После принятого ответа валидатор пересчитывает missing_fields и is_valid.
8. Буквальное исполнение листа БТ-ПН-О сохраняется и выводится.
9. Исторические fixtures на 21 позицию читаются как UTF-8 независимо от кодовой страницы Windows.

Сохраняются исходное количество, консолидация одинаковых товаров, кг→т, история, права и контроль полноты. В PR #2 нет изменений схемы SQLite, зависимостей, supervisor, скриптов запуска и настроек модели. MetalReference сохранён.

## Безопасное обновление — после отдельного разрешения

### Предварительные условия

Согласовать окно без новых заявок. Повторить HEAD/status, процессы и ready PID; не использовать старые PID для остановки. Подтвердить путь SQLite и свободное место вне Git. Не менять .env, Task Scheduler, supervisor, окружение, сеть и модель. Если main изменился — сначала изучить новые коммиты, не принимать новый SHA автоматически.

~~~powershell
$ProjectDir = Join-Path $env:USERPROFILE 'uvm_ai_operator'
$OldHead = '37fed7e6375cfa248c798e4106e1ef5d876c29d9'
$Target = 'afef58d4de17096ce55b2f0241c96cbf7ae205af'
Set-Location -LiteralPath $ProjectDir
git status --porcelain=v1
git branch --show-current
git rev-parse HEAD
git ls-remote origin refs/heads/main
~~~

При локальных изменениях, другой ветке/HEAD — остановиться, ничего не очищать.

### Согласованный backup

Использовать sqlite3.Connection.backup из mode=ro, а не прямое копирование работающего DB/WAL. Сделать снимок до остановки. После корректной остановки повторить блок в новом уникальном каталоге: второй снимок — финальная точка отката.

Следующий блок — исключительно для будущего разрешённого обновления. DbPath сначала подтвердить как runtime-путь.

~~~powershell
$DbPath = Join-Path $ProjectDir 'operator.sqlite3'
$BackupDir = Join-Path (Join-Path $env:USERPROFILE 'uvm_ai_operator_backups') ('p0_' + (Get-Date -Format 'yyyyMMdd_HHmmss') + '_' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $BackupDir -ErrorAction Stop | Out-Null
$BackupPath = Join-Path $BackupDir 'operator.sqlite3'
@'
from pathlib import Path
import hashlib, json, sqlite3, sys
source_path, backup_path = [Path(p).resolve() for p in sys.argv[1:3]]
if not source_path.is_file() or backup_path.exists():
    raise SystemExit("Missing source or destination already exists")
source = sqlite3.connect(source_path.as_uri() + "?mode=ro", uri=True, timeout=30)
copy = sqlite3.connect(backup_path, timeout=30)
try:
    source.backup(copy)
    if [row[0] for row in copy.execute("PRAGMA integrity_check")] != ["ok"]:
        raise SystemExit("Backup integrity check failed")
    tables = ("telegram_active", "telegram_history", "telegram_state",
              "telegram_access_user", "telegram_access_event",
              "telegram_access_bootstrap", "telegram_access_claim_attempt")
    names = {row[0] for row in copy.execute(
        "SELECT name FROM sqlite_master WHERE type='table'")}
    counts = {name: copy.execute('SELECT COUNT(*) FROM "' + name + '"').fetchone()[0]
              for name in tables if name in names}
    manifest = {"integrity_check": "ok", "counts": counts}
    backup_path.with_suffix(".manifest.json").write_text(
        json.dumps(manifest, indent=2), encoding="utf-8")
finally:
    copy.close()
    source.close()
print("integrity_check=ok")
print("backup_sha256=" + hashlib.sha256(backup_path.read_bytes()).hexdigest())
'@ | & .\.venv\Scripts\python.exe -X utf8 - $DbPath $BackupPath
if ($LASTEXITCODE -ne 0) { throw 'Backup failed; stop deployment' }
~~~

Backup и manifest остаются локальными вне Git. Защитить их как production БД; не публиковать тексты, JSON заявок, user ID и права отдельных людей. Manifest содержит агрегатные количества. Перед первым ручным испытанием локально сравнить содержимое таблиц прав и активных заявок до/после, выводя только итог равенства; одних количеств недостаточно для доказательства сохранности.

### Остановка и обновление

~~~powershell

~~~

При ошибке либо живых процессах остановить процедуру. Не применять Stop-Process, не убирать maintenance-маркер. Дождаться завершения всех узлов подтверждённой цепочки этого каталога. Посторонние Python не трогать. Затем создать финальный backup новым каталогом по предыдущему разделу.

Перед применением выполнить pytest новой версии в отдельной проверочной копии с существующим окружением и временными SQLite. main.py там не запускать. Проверочная копия и её Git-метаданные создаются только в рамках будущего разрешённого обновления; production-ветка от этого не переключается.

Записать фактический результат. Ничего не устанавливать и не удалять. При провале тестов новый бот не запускать.

~~~powershell
git merge --ff-only $Target
if ($LASTEXITCODE -ne 0) { throw 'Update failed; stop' }
git rev-parse HEAD
git status --porcelain=v1
~~~

HEAD должен быть Target, дерево — чистым. Не применять reset --hard, rebase, force push или автоматическую установку зависимостей.

Подтвердить отсутствие старой цепочки. Запустить существующий скрипт ровно один раз; его бюджет заменяет повторные ручные запуски.


Проверить новый ready PID и время, единственную цепочку worker и OS-блокировку; новые записи успешной инициализации/polling_connected; отсутствие 409, traceback и SQLite-ошибок; стабильность несколько минут; HEAD Target; сохранность данных/прав и существующего задания. Не изменять настройки модели и reasoning.

Ready-маркер не подтверждает нормализацию. Сообщения пользователям самостоятельно не отправлять. Администратор начинает испытания после отчёта об успешном запуске.

## Откат

Если новый старт неуспешен: stop-telegram.ps1, maintenance-маркер, проверка завершения всех процессов. При неопределённом состоянии остановиться без новых запусков.

Откат только кода при чистом дереве:

~~~powershell
git switch --detach $OldHead
if ($LASTEXITCODE -ne 0) { throw 'Rollback failed; stop' }
git rev-parse HEAD
git status --porcelain=v1
# Только после подтверждения отсутствия процессов и совместимости БД:
& .\start-telegram.ps1 -StartupAttempts 2
~~~

Detached HEAD — временное явно зафиксированное состояние; main и история не переписываются. Возвращение на main — отдельное действие после диагностики.

Исправную SQLite сохранять: схема не меняется. Автоматическая замена старым снимком может потерять новые заявки. При подтверждённой порче и отдельном разрешении сначала сохранить диагностический снимок текущей БД, затем при остановленных процессах восстановить проверенный backup через SQLite backup API и проверить integrity_check. Не заменять живой DB/WAL/SHM напрямую. Без разрешения данные не восстанавливать. Только при отдельно разрешённом восстановлении, подтверждённой остановке всех подключающихся процессов и сохранённом текущем снимке:

~~~powershell
@'
from pathlib import Path
import sqlite3, sys
good_path, target_path = [Path(p).resolve() for p in sys.argv[1:3]]
if not good_path.is_file() or good_path == target_path:
    raise SystemExit("Invalid restore source")
good = sqlite3.connect(good_path.as_uri() + "?mode=ro", uri=True, timeout=30)
try:
    if [row[0] for row in good.execute("PRAGMA integrity_check")] != ["ok"]:
        raise SystemExit("Source integrity check failed")
    target = sqlite3.connect(target_path, timeout=30)
    try:
        good.backup(target)
        if [row[0] for row in target.execute("PRAGMA integrity_check")] != ["ok"]:
            raise SystemExit("Restored DB integrity check failed")
    finally:
        target.close()
finally:
    good.close()
print("restore_integrity_check=ok")
'@ | & .\.venv\Scripts\python.exe -X utf8 - $BackupPath $DbPath
if ($LASTEXITCODE -ne 0) { throw 'Restore failed; do not start' }
~~~

Перед командой BackupPath должен указывать на финальный проверенный снимок до обновления, а DbPath — на подтверждённую production БД. Эта команда изменяет БД и не разрешена одной лишь подготовкой документа.

## Критерии окончательной приёмки P0

- Разрешённое обновление выполнено, одна polling-цепочка устойчива, backup проверен, данные и права сохранены.

- Нет вымышленного, пропущенного или повторно использованного товара; консолидация сохраняет вклад каждого исходного товара.
- Марки/ГОСТ/исполнения/количества/единицы сохранены; конфликты не приводят к частичной записи.
- Уточнения продолжают прежний контекст, валидность пересчитывается, история сохранена.
- Повторяемые сбои имеют безопасную диагностику и воспроизводимый вход. Mock AI не заменяет реальную приёмку.
- Результаты и допустимые ограничения явно приняты владельцем. До этого P0 подготовлен к приёмке, но не объявлен полностью принятым.

## Известные ограничения

- Отсутствует внешний HTML fixture 23MET; одна стандартная проверка остаётся непроходимой без него.
- Нет подтверждённой новой серии реальных LLM-прогонов и полного исходника на 16 труб.
- Не подтверждено отсутствие runtime-переопределения OPERATOR_DB — обязательный gate перед backup.
- Геометрические поля остаются float, количество — Decimal. Общих межполевых правил геометрической совместимости существующий валидатор не задаёт; полноту размеров нельзя считать нормативным подтверждением изделия.
- Автозапуск — при входе текущего пользователя, не до входа при старте Windows; выход пользователя завершает интерактивную эксплуатационную сессию.
- Полная отмена последнего сохранённого изменения не реализована; ожидающую операцию можно отменить, поля корректируются существующими командами.
- Ready, техническая mergeability и отсутствие CI-статусов не доказывают качество LLM.

## Следующий приоритет

После приёмки P0 — исследование архитектуры расчёта массы металлопроката с GPT и внешними онлайн-калькуляторами, включая 23MET, без обязательного обращения к MetalReference.

Исследовать ответственность GPT за извлечение и подбор метода, проверяемые входы/ответ внешнего калькулятора, источники и статус результата, Decimal/единицы/округление, отличия расчётной оценки от нормативной и фактической массы, сетевые ошибки/лимиты и безопасное повторение. Не обходить ограничения сайтов и HTTP 429. Предложить архитектуру с доказательствами применимости перед расширением категорий.

Существующий MetalReference не удалять и не изменять. Это будущая исследовательская задача; новые калькуляторы и функции в документационной ветке не разрабатываются.

### Зафиксированная последовательность после P0

1. Онлайн-калькуляторы металлопроката: исследовать 23MET и альтернативы по доступности, точности, допустимости автоматического обращения, ограничениям и полноте номенклатуры. GPT выбирает подходящий расчёт; Python проверяет исходные позиции, единицы, арифметику и результат. Целевой вход — спецификации в шт., м, пог. м, кг или м²; выход — нормализованная заявка с обоснованной массой в тоннах.
2. Упрощение архитектуры: после реальных испытаний пересмотреть необходимость регулярных выражений и эвристик. Это направление исследования, а не разрешение убрать текущие проверки без доказательств.
