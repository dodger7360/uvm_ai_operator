# Metal Reference

## Назначение

Metal Reference — внутренняя машиночитаемая база знаний металлопроката, которая описывает сортамент, используемый УВМ-Сталь. Она нужна AI-оператору, чтобы понимать заявки, распознавать названия продукции и сопоставлять их с подтверждёнными типами и характеристиками.

Это не пользовательский каталог и не самостоятельная витрина. Документ фиксирует архитектурные границы и решения; он не задаёт схему БД и не описывает реализацию ingestion.

В знаниях Metal Reference должны быть представлены виды металлопроката, сортаменты и типоразмеры, размеры, марки и классы, исполнения, ГОСТ/ТУ и связанные документы, технические характеристики, единицы измерения, нормативный и расчётный вес, aliases и варианты написания, а также происхождение каждого значения.

## Граница ассортимента

Metal Reference не копирует весь каталог 23MET. Первая версия охватывает ассортимент, нужный УВМ-Сталь. Основной источник определения поддерживаемого ассортимента — реальные складские данные компании.

Поддерживаемый компанией сортамент не равен наличию товара на складе в данный момент. Остатки меняются; отсутствие остатка не исключает товар из поддерживаемого сортамента. Складские данные помогают установить scope и описывают текущее наличие отдельно от устойчивых справочных характеристик.

## Роли компонентов

- **Metal Reference** хранит подтверждённые сведения о сортаменте и связи между продукцией, типоразмерами, исполнениями, марками/классами, нормативами и техническими значениями.
- **AI** понимает свободную формулировку заявки и предлагает соответствие знаниям. Он не является источником фактов, ГОСТов, марок или массы и не должен додумывать отсутствующие параметры.
- **Python** выполняет детерминированное разрешение характеристик и, в будущем, расчёты по подтверждённым данным и правилам. Теоретическая масса не поручается AI.
- **Normalization Workbench** остаётся источником истины для исходного пользовательского текста и явно заданных пользователем характеристик. Подсказка Metal Reference не переписывает исходный факт, не добавляет стандартную длину без основания и не удаляет параметр, если его нет в источнике.
- **Складские данные** отражают ассортимент и меняющиеся остатки. Остаток не является частью постоянной идентичности типоразмера.

Если пользователь задаёт альтернативы, например два допустимых раскроя через «или», это одна закупочная позиция с несколькими разрешёнными вариантами. Справочник не должен автоматически выбирать один из них или превращать их в независимые позиции.

## Содержание справочных знаний

Для поддерживаемых категорий Metal Reference должна позволять связывать:

- понятие продукции, тип/сортамент и типоразмер;
- геометрические размеры и их единицы;
- марку стали, класс, исполнение и форму поставки, когда они явно подтверждены;
- ГОСТ/ТУ, варианты нормативов и документы;
- технические характеристики с исходными названиями, значениями и единицами;
- нормативный вес и расчётный вес с указанием основания;
- aliases и варианты написания для сопоставления пользовательского текста;
- каждое значение с источником и provenance.

Нормативные варианты сохраняются раздельно, если источник показывает разные значения или схемы. Значения разных ГОСТ/ТУ нельзя автоматически сливать в одно описание типоразмера.

Теоретический вес и вычисленный вес различаются по смыслу. Расчёт допускается только детерминированно, когда подтверждены необходимые геометрические параметры, формула, единицы и применимый материал/норматив. Неизвестные значения остаются неизвестными.

### Плотность стали

В локальном HTML 23MET для листа сохранён явный выбор стали `ст08` с вызовом `calc_set_stal_koef(this,7.871)` и атрибутом `data-w="7871 кг/м³"`. Это подтверждает плотность **7.871 т/м³** для данного выбора и может служить входным значением детерминированного расчёта там, где применима соответствующая геометрическая формула. Значение нужно хранить с provenance и условиями применимости; оно не объявляется универсальной плотностью для всех металлов и исполнений.

Тот же HTML содержит скрытое начальное значение `calc_stal_koef1=7.85`. Оно не отменяет явного варианта `ст08` с 7.871 и подчёркивает необходимость сохранять контекст выбора и происхождение параметра.

## Источники и provenance

23MET — один из источников данных для внутренней базы. Используются разные части сайта по назначению, а не по URL:

- `/price` содержит не только цены: оттуда могут поступать категории, товары, сортаменты, типоразмеры, размеры, марки, исполнения, нормативы, фильтры, связи характеристик, калькуляционные параметры и ссылки на справочные материалы.
- `/spravka` может давать нормативные варианты, технические таблицы, размеры, массу и схемы.
- `/gosts`, `/weight` и связанные калькуляторы/механизмы сайта могут быть источниками документов, весовых данных или параметров расчёта.

Одна страница `/price` может содержать как Reference Data, так и Market Data. При будущей обработке значения классифицируются по назначению и сохраняются с происхождением; URL сам по себе не определяет тип данных.

Для каждого принятого значения важно сохранять исходное представление, единицу, источник/URL, выбранный норматив или вариант, а также сведения, достаточные для аудита происхождения. Неинтерпретированные строки и связи источника не отбрасываются только потому, что пока нет безопасного типизированного поля.

## Reference Data и будущие Market Data

**Reference Data** описывают продукцию и нормативно-технические свойства: категорию, типоразмер, размеры, марку/класс, исполнение, ГОСТ/ТУ, документы, массу, единицы и подтверждённые правила расчёта.

**Market Data** — меняющиеся предложения: цены, поставщики, наличие у поставщика, город, коммерческие условия и история цен. Они могут быть получены с тех же страниц `/price`, но хранятся и используются отдельно от справочной идентичности товара.

Разделение выполняется по назначению данных, а не по разделам сайта.

## Связь с Normalization Workbench

Metal Reference дополняет Workbench подтверждёнными знаниями о сортаменте и помогает детерминированно сопоставить пользовательские названия с типом и характеристиками. Workbench сохраняет пользовательский исходный текст и явно указанные факты. Справочник предоставляет кандидатов и основания для интерпретации, но не меняет запрос без пользовательского основания. Расчётные результаты должны быть воспроизводимы Python и сопровождаться исходными значениями, единицами и provenance.

На этой стадии не утверждаются структура базы данных, production ingestion, scraper или интеграционные изменения Workbench.
